# Подготовка среды для занятий

Основные материалы и проверки стенда доступны без модели и внешнего API. Для опытов с моделью отдельно нужны готовые веса и сервер ядра. Для исполнения сгенерированного кода нужна проверенная изолированная среда. Для дообучения используется отдельное Python окружение.

Для начала пройди [урок 00 об интерфейсе](../lessons/00-interface/README.md). В нём нужен только установленный tmux, без весов и модельного сервера. Подготовку ядра ниже выполняют перед настоящими запросами урока 01. Команда запуска сама создаёт два терминала; пользоваться tmux вручную с нуля не требуется.

## Проверка перед каждым запуском урока

Для уроков 00–04 команда `./lab classroom start --lesson NN --split` выполняет подготовку автоматически до создания учебной сессии: проверяет подключение преподавателя, запускает нужный модельный сервер и получает пробный ответ. Для 00 теперь также требуется локальная модель base: в конце вводного урока есть настоящий запрос. Недостающие публичные веса и локальные зависимости подготавливаются при запуске; системные пакеты и авторизация преподавателя нужны заранее. Для уроков 01–03 недостающий llama.cpp b12380 собирается из закреплённого исходника при наличии git, cmake и C++. Для 04 используется отдельная CPU-среда обучения, без запуска обучения. Логи и отчёты находятся в `results/preparation/`; ошибочный запуск не создаёт журнал ученика. `classroom create` по-прежнему только создаёт сессию и не подтверждает готовность.

Перед открытием класса другим способом или рекомендацией команды запуска без выполненной автоматической подготовки автор проверяет текущую готовность зависимостей выбранного урока. Старый успешный прогон и наличие файлов не подтверждают, что процессы работают сейчас.

- Выполни `./lab doctor` и `./lab validate`: они проверяют локальную подготовку и материалы, но не соединение с моделью.
- Для урока с запросами к модели проверь фактический endpoint и профиль весов, дождись загрузки сервера и выполни короткий настоящий запрос по инструкции подготовки урока. Сохрани вход, настройки, ответ или ошибку в отдельный файл подготовки в `results/`, вне журнала ученика. Для урока 01 используй [SETUP.md](../lessons/01-black-box/SETUP.md), записав новый результат вместо перезаписи прошлого свидетельства.
- Проверь доступность выбранного подключения преподавателя штатным способом, без вывода токенов и без учебного диалога. Для урока 00 проверяются и преподаватель, и локальная модель base.
- Если урок использует обучение, контейнеры или дополнительные инструменты, проверь соответствующее окружение и подготовленные зависимости по его инструкции. Обучение не запускается при подготовке. В автоматической подготовке уроков 00–04 разрешены описанные выше загрузки публичных весов и установка закреплённых пакетов в локальную среду; ручная проверка остальных уроков их не выполняет.

При неуспехе сначала восстанови нужный компонент в пределах разрешённой подготовки и повтори проверку. До успешной проверки сообщай, что запуск ещё не готов. Ошибка соединения и HTTP 503 во время загрузки сервера не являются ответом модели. Запуск класса выполняется отдельно по просьбе пользователя; предварительная проверка сама не начинает урок и не засчитывается ученику как опыт.

## Перенос на свой компьютер

Проверенный профиль разработки: Linux x86_64, Python 3.12, CPU Intel i7-1165G7, около 48 GiB RAM, llama.cpp b12380. Это описание измерений, а не минимальные требования и не утверждение о наличии процессов на вашем компьютере. Пакет не содержит бинарников, весов или окружений Python.

Сначала подключите [свой агент как преподавателя](TEACHER_RUNTIME.md), установите tmux и зависимости основного стенда из requirements.txt. `./lab` использует `/usr/bin/python3`; можно явно вызвать Python своего окружения: `python -m coursekit`. Профиль обучения требует отдельного окружения и requirements-training.txt.

Точная версия llama.cpp — b12380, commit e3483e40b (см. run-card уроков 01–02). При запуске уроков 01–03 стенд собирает недостающий runtime из закреплённого исходника автоматически. Для ручной подготовки используйте [официальный репозиторий](https://github.com/ggml-org/llama.cpp/tree/b12380) под свою платформу; положите llama-server в runtime/llama-b12380/. Зафиксируйте параметры сборки и фактическую версию. Если старая сборка не собирается на вашей системе, зафиксируйте отдельный новый профиль и повторите опыты по EXAMPLES.md урока.

```bash
./lab doctor
./lab validate
```

Эти команды не начинают занятие и не проверяют доступность преподавателя или модельного сервера. Проверка перед каждым запуском остаётся обязательной. Основные зависимости закреплены в requirements.txt; при обновлении повторите проверки.

## Профили модели

В [resources/models.json](../resources/models.json) зафиксированы два исходных профиля Qwen2.5 1.5B, ревизии, размеры и SHA256. Это кандидаты для пилота: их поведение в упражнениях и пригодность для финальной игры ещё предстоит измерить. Если для игры потребуется более сильная модель, смена профиля будет явно отражена в исходном измерении и карточках опытов.

План подготовки одного профиля не выполняет загрузку:

```bash
/usr/bin/python3 tools/prepare_model.py --variant base
/usr/bin/python3 tools/prepare_model.py --variant instruct
```

Когда начнётся подготовка весов, ученик явно запускает нужную загрузку:

```bash
/usr/bin/python3 tools/prepare_model.py --variant base --download
```

Для версии инструкций заменить `base` на `instruct`. Каждый файл занимает примерно 1 GiB; скорость сети определяет время ожидания. Программа проверяет размер и SHA256 до объявления файла готовым. Существующие неподходящие файлы и незавершённые загрузки сохраняются для отдельного решения; автоматической перезаписи нет.

Запуск базовой модели в отдельном терминале:

```bash
runtime/llama-b12380/llama-server \
  --model models/qwen2.5-1.5b-base-q4_k_m.gguf \
  --host 127.0.0.1 --port 8088 --ctx-size 4096 --threads 4 --device none
```

Для явно отмеченного перехода к версии инструкций остановить сервер и заменить путь весов на `models/qwen2.5-1.5b-instruct-q4_k_m.gguf`. Не делать этого посреди сравнения двух промптов или продолжения сохранённой задачи. Проверять фактический формат входа: `/completion` получает точный текст, а роли диалога сами по себе не появляются от названия модели.

Первый настоящий запрос:

```bash
./lab complete --prompt-file lessons/01-black-box/prompts/baseline.txt \
  --endpoint http://127.0.0.1:8088 --max-tokens 128 \
  --temperature 0 --seed 42 --output results/first-completion.json
```

Файл содержит `text`, `metadata` и `events`. Модель не получает доступ к файлам или командам только от этого запроса. Сервер на своей арендованной машине поддерживается тем же HTTP интерфейсом; `--allow-remote` нужен для явно указанного внешнего endpoint. Сервис API по подписке в эту схему сейчас не подключён.

## Исполнение кода

До занятий 10–12 нужно отдельно проверить Docker daemon и заранее подготовленный образ. Стенд не загружает образ автоматически. Проверка отсутствующего образа заканчивается отказом.

Пример проверки уже подготовленного Bash образа:

```bash
mkdir -p work/sandbox-smoke
./lab sandbox-check --workspace work/sandbox-smoke --sandbox-image bash:5.2
```

Для OpenSpec нужен собственный подготовленный образ из [containers/Dockerfile](../containers/Dockerfile) с именем `llm-course-sandbox:1.0`. Сборка относится к подготовке, имеет отдельные требования к сети, диску и Docker. Она не была выполнена при написании материалов. Перед пилотом нужно сохранить фактический image ID, проверить версию CLI внутри образа и реальную остановку контейнера по таймауту. Во время действий агента образ работает без сети и загрузки пакетов.

Состояние и отчёты помещаются в `results/`, рабочие файлы агента — в отдельные каталоги `work/`. Каталог программы нельзя назначать рабочим каталогом агента. Не использовать папку, содержащую другие проекты или личные данные.

## Дообучение

[Занятие 04](../lessons/04-training-data/README.md) готовит данные и исходное измерение, [занятие 05](../lessons/05-fine-tuning/README.md) запускает настоящее изменение адаптера на маленькой модели. Настройки и скрипты одинаковы для подходящего локального компьютера и арендованной машины; длительность и память измеряются на выбранном оборудовании.

Для опубликованного авторского пилота веса проверялись и выполнялось настоящее обучение; это не означает, что зависимости уже установлены на вашей машине. Выбор API и его расходы зависят от подключения преподавателя. Выбор машины и платный запуск не требуются для чтения материалов, проверки генератора данных или знакомства с устройством стенда.
