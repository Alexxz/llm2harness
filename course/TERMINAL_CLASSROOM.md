# Совместное занятие в терминале

Ученик работает в учебной консоли своего терминала: меняет текст и настройки, запускает опыт и видит результат. Преподаватель получает события той же сессии, задаёт уточнения, отправляет советы и управляет разрешением новых запусков. Копировать каждый вывод в чат не требуется.

В режиме `--split` преподаватель работает отдельным компонентом через `codex exec`. Он автоматически читает новые события, отвечает на вопросы, сохраняет заметки о прогрессе. Каждый ход — отдельный ограниченный вызов с восстановлением истории из журнала. Исследуемая учеником модель подключается отдельно; даже урок 00 использует модель преподавателя.

## Запуск ученика

Рекомендуемый режим — две области одного терминала. Терминал преподавателя показывает материалы и подсказки. Терминал ученика принимает команды опытов и показывает результаты. Все вопросы, ответы и обсуждение идут только в канале преподавателя. Обе терминальные области относятся к одной сессии и одному журналу.

Они подписаны «Терминал преподавателя · УРОК» и «Терминал ученика · ЭКСПЕРИМЕНТ». F2 сразу выбирает материалы, F3 — команды. Ctrl+h открывает помощь, Esc закрывает. Все вопросы и ответы преподавателю пиши только в канале преподавателя.

Терминал преподавателя отображает цветной Markdown. Пиши вопросы и ответы обычным текстом прямо слева. Команды: `/lesson` — материалы, `/basics` — памятка, `/retry` — повтор после ошибки, `/exit` — закрыть занятие. Никаких сообщений в чат автора или специальных слов для продолжения не нужно.

В обычном терминале:

```bash
cd /path/to/llm2harness
./lab classroom start --lesson 00 --split
```

Требуются установленный `codex` с рабочим подключением и Node.js 24. В текущем окружении адаптер добавляет установленный Node.js 24.22.0 в PATH. Установка программ и загрузка весов при запуске занятия не выполняются.

Преподаватель начнёт с первого задания. При ошибке подключения появится сообщение; после исправления введи `/retry`. Преподаватель вызывается напрямую через преподаватель без Codex и MCP. Ученическая модель остаётся локальной; личный OpenAI API не требуется.

## Первый совместный опыт

Сначала преподаватель объясняет операцию «вход — продолжение», разбирает короткий пример и проверяет, понятна ли задача. Затем показывает назначение одной команды. Например, `show` только выводит подготовленный текст и ничего не отправляет модели:

```text
show
```

Ученик читает конкретный блок «ТЕКСТ ДЛЯ МОДЕЛИ — ВХОД» и обсуждает задачу. Следом преподаватель отдельно объясняет `doctor`: проверку локальных программ и файлов без сети, которая ещё не подтверждает работающий сервер. Её отчёт даётся обычным текстом; полные данные остаются в журнале и доступны через `status`.

До первого `run` преподаватель завершает подготовку, объясняет настройки и просит прогноз уже понятного опыта. После разрешения запуска ученик выполняет согласованные действия по одному:

```text
run
set temperature 0.7
run
```

В журнале остаются оба точных входа, настройки, события запроса и результаты. Преподаватель проверяет, что ученик изменил один фактор, и предлагает следующий опыт. Настройка температуры сама по себе не доказывает улучшения ответа.

Свой промпт вводится без внешнего редактора:

```text
edit
Продолжи одним предложением: Сегодня я впервые исследую языковую модель и
::end
show
run
```

`::cancel` отменяет редактирование. Текст остаётся данными до явного запуска. Совет преподавателя также не исполняется и не подмешивается к запросу модели.

## Действия преподавателя

Перед подключением прочитайте [руководство преподавателя](TEACHER_GUIDE.md) и `INSTRUCTOR.md` текущего занятия. Оно определяет, как превратить наблюдение и управление терминалом в помощь ученику: диагностировать затруднение, предложить следующий шаг, вернуться к исходной ошибке и проверить новый случай.

Ниже `SESSION` — идентификатор, напечатанный консолью. Команды преподавателя выполняются отдельно от приглашения ученика:

```bash
./lab classroom list
./lab classroom observe SESSION --json
./lab classroom advise SESSION --message 'Сначала запиши прогноз. Измени только длину ответа и сравни окончания.'
./lab classroom resume SESSION
```

В JSON ответе наблюдения есть состояние, новые события и `cursor`. Чтобы дождаться следующего действия, преподаватель передаёт полученное число:

```bash
./lab classroom observe SESSION --after 12 --wait-seconds 30 --json
```

Это один ограниченный запрос наблюдения. Во время активного занятия ассистент повторяет его по мере опытов, разбирает результаты и отправляет советы. Для человека можно убрать `--json`: вывод будет удобен для чтения.

Подсказка преподавателя отображается в материалах; команды и результаты — в терминале ученика. Вопрос о непонятном выводе пиши в канале преподавателя. Преподаватель сам восстановит точный вход и результат из журнала.

Специального сигнала для продолжения нет. Расскажи в канале преподавателя, что увидел, или задай вопрос. Сообщение слева доставляется отдельному преподавателю автоматически.

## Пауза и остановка

```bash
./lab classroom pause SESSION
./lab classroom stop SESSION
./lab classroom resume SESSION
./lab classroom close SESSION
```

`pause` немедленно закрывает допуск новых запусков; текущий опыт может закончиться. `stop` закрывает допуск и запрашивает остановку конкретного активного опыта. В журнале отдельно видны запрос остановки и фактическое завершение. Преподаватель проверяет подтверждение, а не считает отправленную команду доказательством остановки.

Для адресной остановки можно передать `--run-id` из наблюдаемого состояния. Запоздавшая команда для старого опыта не должна прерывать новый. Преподаватель не посылает сигнал произвольному PID из файла; этим занимается владелец живого процесса опыта.

`resume` только открывает допуск новых опытов. Он не повторяет прерванное действие агента. Если после принудительного завершения исход записей или уборки контейнера не подтверждён, это явно отмечается; преподаватель разбирает состояние перед продолжением. Остановка локального HTTP клиента не подтверждает прекращение вычислений отдельно запущенного сервера модели.

`close` завершает учебную сессию и запрашивает остановку активного опыта. `exit` ученика сохраняет сессию на паузе. Для подключения к ней позже:

```bash
./lab classroom student SESSION
```

Чтобы открыть сохранённую сессию с двумя областями, добавь `--split`: `./lab classroom student SESSION --split`.

Одновременно сессию ведёт только один терминал ученика.

## Подключение компонентов курса

Изначально доступны подготовка и один текстовый запрос. Перед новым этапом преподаватель явно разрешает компоненты:

```bash
./lab classroom permit SESSION --capabilities doctor,complete,agent
./lab classroom permit SESSION --capabilities doctor,complete,agent,mcp,skill
```

Во втором случае ученик может включить навык и MCP. Для исполнения кода преподаватель отдельно разрешает `bash`; нужен заранее подготовленный контейнер. Выбор инструментов агента остаётся явным:

```text
set tools read_file,write_file
set max_steps 8
set max_requests 8
agent
```

`agent` начинает новую ограниченную задачу по текущему тексту. Если агент задаёт вопросы и ждёт пользователя, команда `answer` позволяет ввести ответ до `::end` и продолжить ту же задачу. Это отличается от `resume` преподавателя, который управляет допуском сессии.

Другие команды консоли:

| Команда | Действие |
|---|---|
| `load baseline`, `load variation` | Загрузить промпт текущего занятия. |
| `schema schema.json`, `schema off` | Подключить схему из текущего занятия или отключить её. |
| `copy fixtures/stock.json stock.json` | Скопировать актив текущего занятия в рабочую папку. |
| `read notes.txt`, `write notes.txt` | Прочитать или отредактировать учебный файл. |
| `mcp` | Выполнить реальное обнаружение и вызов локального инструмента `read_note`. |
| `bash` | Выполнить текущий текст только в подготовленном контейнере. |
| `set skill on`, `set skill off` | Изменить подключение учебного GrillMe для следующей задачи. |
| `status` | Показать разрешения, настройки и состояние опыта. |

Для OpenSpec используется заранее подготовленный образ `llm-course-sandbox:1.0`, выбранный при `start --sandbox-image`. Ученик не может незаметно заменить endpoint, образ, рабочий каталог или путь навыка из приглашения консоли. Новые параметры относятся к следующему опыту; запущенный опыт сохраняет исходный снимок входа и разрешений.

## Что наблюдает преподаватель

События содержат явно отправленные промпты, настройки, вопросы, предложения действий агента, решения политик, результаты инструментов и причины остановки. События поступают во время вычисления, а не только после финального ответа. У запроса и результата сохраняется общий идентификатор опыта.

Авторитетные данные находятся в `results/classroom/SESSION`, учебные файлы — в `work/classroom/SESSION`. Агент не получает право менять журнал занятия. Управляющие последовательности модели и инструментов отображаются как текст, чтобы вывод не мог менять терминал или изображать команду интерфейса.

Обычные команды личного shell, другие окна терминала, история клавиш и окружающие проекты не записываются. Произвольный shell на хосте в учебной консоли не исполняется. Дополнительные программы подготовки данных и обучения из методичек остаются отдельными явно запускаемыми сценариями; они не становятся наблюдаемыми и останавливаемыми только от открытия консоли. Их подключение к общей диспетчеризации требует отдельного проверенного адаптера.

Роли «ученик» и «преподаватель» — способ совместной работы в одной учётной записи ноутбука, а не система разграничения двух Unix пользователей. Контроль относится к запускам учебной сессии; реальная изоляция сгенерированного кода обеспечивается контейнерным исполнителем.
