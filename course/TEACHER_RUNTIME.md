# Подключение преподавателя

У ученика предполагается собственный агент. Вне занятия он помогает настроить среду, исправить интерфейс, переработать урок и разобраться с переносимостью. Внутри занятия его модель служит интеллектом преподавателя. Это отдельные режимы и контексты: внешний помощник не принимает упражнения вместо преподавателя. Учебная локальная модель — третий, отдельный компонент.

По умолчанию выбран `codex`; также доступны `api` и `command`. Ни один backend не устанавливается и не авторизуется автоматически. Локальные настройки задаются переменными окружения из личного файла **вне репозитория**. Ключи не передаются в аргументах команд, материалах или журнале. После смены подключения нужно закрыть и заново открыть split-терминал: tmux наследует настройки при создании.

## Пример с Codex CLI

Установите и авторизуйте официальный Codex CLI по [инструкции](https://developers.openai.com/codex/cli). Проверьте `codex --version` и `codex exec --help` в своём терминале. Нужны параметры `--ephemeral`, `--ignore-user-config`, `--ignore-rules`, `--output-schema`, `--sandbox` и `--skip-git-repo-check`. Зафиксируйте свою версию CLI и выбранную модель в отчёте подготовки.

```bash
export COURSE_TEACHER_BACKEND=codex
export COURSE_TEACHER_COMMAND=codex
# Необязательно: точный ID доступной вам модели.
# export COURSE_TEACHER_MODEL=...
```

Подготовленный запуск после успешной предварительной проверки: `./lab classroom start --lesson 00 --split`. Эта строка описывает способ запуска, а не подтверждает готовность вашей среды.

Каждый ход — отдельный `codex exec` во временном пустом каталоге; контекст передаётся через stdin, ответ — через JSON Schema и временный файл. Используются read-only sandbox, запрет запросов одобрения, отключение пользовательского конфига, правил, shell, MCP, Apps, плагинов и сторонних навыков в рамках вызова. Персональные настройки не переписываются. Набор флагов сверён с [исходником официального CLI](https://github.com/openai/codex/blob/main/codex-rs/exec/src/cli.rs); синтетические тесты транспорта не заменяют проверку вашей версии. Промпт сам по себе не является границей безопасности; для строго текстового вызова без инструментальной обвязки используйте API.

## Пример с Responses API

Дополнительный SDK не нужен: используется стандартная библиотека Python. Выберите точный ID модели, поддерживающей Responses API и Structured Outputs, в своём API-аккаунте. Не предполагается, что доступ к агенту даёт доступ к платному API.

```bash
export COURSE_TEACHER_BACKEND=api
export COURSE_TEACHER_API_MODEL='ID_ДОСТУПНОЙ_ВАМ_МОДЕЛИ'
read -rsp 'API key: ' OPENAI_API_KEY; echo
export OPENAI_API_KEY
```

Ключ вводится скрыто и не записывается строкой команды. Endpoint по умолчанию — `https://api.openai.com/v1/responses`; `COURSE_TEACHER_API_ENDPOINT` позволяет задать совместимый Responses endpoint. Удалённый адрес требует HTTPS, перенаправления запрещены. Для синтетических локальных проверок разрешён HTTP на loopback. `COURSE_TEACHER_API_PROXY` необязателен: только HTTP(S) URL без логина, пароля, query и пути. Автоматического SSH или подключения к чужой машине нет.

В запросе `tools=[]`, `tool_choice=none`, `store=false`, строгая схема ответа и максимум 4096 выходных токенов. Сетевой timeout не больше 110 секунд, общий — 120; автоматических повторов нет. В журнал попадают ответ, ID модели и usage; диагностика провайдера и заголовки авторизации не публикуются. Внешний сервис получает материалы урока и последние события сессии: учитывайте это при использовании личных данных. API может стоить денег.

## Подключение другого агента

Выберите backend `command` и команду собственного адаптера:

```bash
export COURSE_TEACHER_BACKEND=command
export COURSE_TEACHER_COMMAND='/absolute/path/to/python /absolute/path/to/adapter.py'
```

Команда разбирается в argv без shell; pipe, перенаправления и shell-подстановки не исполняются. Не помещайте ключи в команду. Адаптер получает на stdin один JSON: `instructions` (инструкция преподавателя), `input` (JSON-строка пакета урока), `schema` (схема ответа), `timeout` (секунды). Пакет содержит `materials`, `lesson`, `session`, `events`; для практикума обучения также `learning_lab` с текущим этапом, видимостью окна и ближайшим действием.

Адаптер вызывает агента в отдельном контексте преподавателя и возвращает **только** объект `{"reply":"Объяснение ученику","note":"Подтверждено и осталось","control":"none"}`. Диагностика — в stderr без секретов. `control`: `none`, `pause`, `resume`; это ограниченные сигналы стенду, а не команды ОС. Пустой ответ, лишние поля и неверные типы отклоняются. На ошибке повтор возможен явно через `/retry`; пауза/выход останавливают принадлежащий стенду процесс. Адаптер обязан сам исключить инструменты и скрытые источники контекста своего агента.

См. [исполнимый пример](../examples/teacher_adapter.py): он намеренно не вызывает модель и не годится как преподаватель; показывает только протокол. Реальный вызов добавляется в отмеченное место. Не передавайте внешнему помощнику роль преподавателя автоматически при сообщении об открытом терминале.

## Как вырабатывали поведение

Разработка инструкций и испытания описаны в [TEACHER_DEVELOPMENT.md](TEACHER_DEVELOPMENT.md). Это настройка контекста и методики, а не заявление о дообучении весов преподавателя. Исторические наблюдения не гарантируют такого же поведения нового агента.
