# Структурированный ответ через инструкции и примеры

Для совместной работы открой [учебную консоль с преподавателем](../../course/TERMINAL_CLASSROOM.md): `./lab classroom start --lesson 03` из корня проекта. Промпты, явные запуски и советы этой сессии видны преподавателю; обычные команды других терминалов в журнал не попадают.


## Цель

Получить JSON от модели с помощью текста промпта и проверить три разных свойства: разбирается ли ответ как JSON, соответствует ли он схеме и правильно ли передаёт исходную заявку. Затем добавить примеры в промпт и сравнить результаты на одном наборе задач.

В этом занятии форма ответа управляется текстом входа. Проверка выполняется после генерации; она не исправляет ответ и не ограничивает выбор продолжения. Изменение весов изучаем в занятиях 4–5, а ограничение генерации схемой — в занятии 6.

## Перед началом

Нужны [первое](../01-black-box/README.md) и [второе](../02-dialog/README.md) занятия, подготовленный сервер и карточка выбранного профиля. Для выполнения инструкций удобен утверждённый instruct-профиль. Его название, ревизию и настройки фиксируем до серии; не переключаем модель между исходным и изменённым промптами.

```bash
/usr/bin/python3 -m coursekit doctor
mkdir -p results/03
cp results/02/run-card.json results/03/run-card.json
/usr/bin/python3 -m coursekit prompt 03 baseline
```

Убедись, что скопированная карточка соответствует фактическому серверу. Если сменил профиль, обнови её и повтори исходную серию на новом профиле.

Все заявки и ответы в `fixtures/` выдуманы для проверки стенда. Файлы там не являются результатами работы модели. Настоящие результаты ты получишь и сохранишь в `results/03/`.

| Время | Работа |

| 25–45 минут | Выполнить исходный набор из шести заявок. |

## Опыты

### Три уровня правильности без обращения к модели

Прочитай [правила извлечения](prompts/baseline.txt), [схему](schema.json) и [набор заявок](fixtures/evaluation-cases.json). Выход содержит три поля:

- `drink`: `tea`, `coffee` или `null`, если допустимый напиток не указан.
- `cups`: целое число от 1 до 20 или `null`, если количество не указано либо выходит за диапазон.
- `urgent`: логическое значение, показывающее явный запрос срочного исполнения.

Запусти проверку заданных фикстур:

```bash
/usr/bin/python3 lessons/03-structured-prompts/score.py --responses lessons/03-structured-prompts/fixtures/responses --source offline_fixture --output results/03/fixture-report.json
cat results/03/fixture-report.json
```

Здесь пять заданных файлов на шесть задач. Ожидаемые счётчики: пять доступных ответов, четыре синтаксически допустимых JSON, три соответствия схеме и два совпадения с содержательным эталоном. Это проверка логики измерения на искусственных входах, а не показатель качества модели. Для шестой задачи файл специально отсутствует: он остаётся в общем числе задач.

Объясни, почему корректный JSON `{"drink":"coffee","cups":1,"urgent":false}` неверен для заявки «Одну чашку какао, обычный заказ»: схема допускает его поля, но напиток определён неправильно по правилам задачи.

### Первый настоящий ответ

До запуска предположи, добавит ли модель пояснение, обрамит ли ответ блоком кода и верно ли извлечёт поля.

```bash
/usr/bin/python3 -m coursekit complete --prompt-file lessons/03-structured-prompts/prompts/baseline.txt --endpoint http://127.0.0.1:8088 --max-tokens 128 --temperature 0 --seed 42 --output results/03/first.json
jq -r '.text' results/03/first.json > results/03/first-response.txt
/usr/bin/python3 -m coursekit check-json --schema lessons/03-structured-prompts/schema.json --input results/03/first-response.txt
```

`first.json` — служебная оболочка клиента; JSON, который обещала модель, находится в поле `text`. Поэтому проверке передаём извлечённый текст. Если модель добавила пояснение или блок Markdown, сохраняем исходный ответ и отмечаем ошибку. Не удаляй обрамление незаметно: это изменило бы способ измерения.

Успех проверки схемы означает только соответствие структуры. Сопоставь значения с заявкой отдельно: кофе, три чашки, срочный заказ.

### Исходная серия и серия с примерами

Изменяем только наличие двух примеров во входе. Правила, текущая заявка, модель, настройки и критерии одинаковы. Дополнительный текст увеличивает длину входа; зафиксируй это как часть вмешательства «добавили примеры», а не как отдельное обучение.

```bash
diff -u lessons/03-structured-prompts/prompts/baseline.txt lessons/03-structured-prompts/prompts/variation.txt
/usr/bin/python3 lessons/03-structured-prompts/render_cases.py --output results/03/inputs
```

Помощник создаст по шесть входов в каталогах `inputs/baseline` и `inputs/variation`. Внутри пары различаются только добавленные примеры. Прочитай одну пару и заранее запиши, на каких заявках ожидаешь пользу или ухудшение.

```bash
for course_mode in baseline variation; do
  mkdir -p "results/03/$course_mode"
  for course_prompt in "results/03/inputs/$course_mode/"*.txt; do
    course_case="${course_prompt##*/}"
    course_case="${course_case%.txt}"
    /usr/bin/python3 -m coursekit complete --prompt-file "$course_prompt" --endpoint http://127.0.0.1:8088 --max-tokens 128 --temperature 0 --seed 42 --output "results/03/$course_mode/$course_case.json"
  done
  /usr/bin/python3 lessons/03-structured-prompts/score.py --responses "results/03/$course_mode" --source live_model --output "results/03/$course_mode-report.json"
done
```

Открой два отчёта. Для каждой задачи сравни `json_valid`, `schema_valid` и `content_correct`. Счётчики делятся на один и тот же знаменатель — шесть задач, включая отсутствующие или ошибочные результаты. При сбое транспорта восстанови запрос отдельно и запиши причину; не объявляй серию успешной из-за исключения неудачных задач.

Серия из шести примеров — учебная диагностика. Она не даёт надёжной общей оценки модели. Добавленные примеры могут улучшить часть ответов, не изменить их или ухудшить. Значимый результат практики — измерить реальный эффект и найти конкретные случаи, а не получить заранее назначенный процент.

### Разбираем неудачу без автоматического исправления

Выбери один ошибочный настоящий ответ. Если ошибок нет, используй [заданные фикстуры](fixtures/README.md), явно подписав источник. Классифицируй сбой:

1. Текст не является ровно одним JSON-значением.
2. JSON разбирается, но не соответствует схеме.
3. Структура допустима, но значения не соответствуют заявке.

Придумай изменение одной инструкции или одного примера, которое может помочь. Сохрани новую версию промпта отдельно и повтори только сопоставимую пару. Проверка после ответа не гарантирует, что следующий ответ модели будет лучше.

## Ожидаемые наблюдения

Инструкция о JSON и примеры меняют вход. Проверяющая программа измеряет результат после получения. Эти компоненты не обновляют веса и сами не заставляют модель выдавать допустимую структуру во время генерации.

Три уровня оценки могут расходиться: структурно допустимый ответ бывает содержательно неверным. Возможен и безошибочный результат на всех шести задачах; он ограничен этим набором и текущей конфигурацией.

## Если результат отличается

- Все ответы содержат пояснения: проверь вариант весов и точный промпт. Затем исследуй более явное указание формы как отдельное изменение.
- Ответ обрезан: сохрани его, увеличь лимит для обеих групп и повтори сопоставимые запросы. Нельзя улучшать лимит только у одной стороны сравнения и приписывать разницу примерам.
- Схема принимает неверный напиток: она не знает исходную заявку. Эту ошибку обнаруживает содержательный эталон.
- После примеров стало хуже: проверь, чему именно учат примеры, и не скрывай ухудшение. Два удачных образца не гарантируют обобщения.
- В отчёте отсутствуют ответы: проверь имена `c01.json` … `c06.json` и журнал запросов. Отсутствующий файл не исключается из общего числа.
- Проверяющая программа не запускается: проверь системный `/usr/bin/python3` и `jsonschema` в подготовленной среде.

## Что сохранить

Сохрани карточку модели, 12 отправленных входов, исходные ответы обеих серий, два отчёта и заметки с прогнозами. В выводах перечисли конкретные изменения по задачам и отметь, где улучшился формат, а где содержание. Придуманные фикстуры и настоящие результаты храни раздельно.

## Критерии завершения

1. Ученик на конкретных файлах различает синтаксис JSON, соответствие схеме и содержательную правильность.
2. Есть две полные сопоставимые реальные серии на одном наборе из шести задач.
3. Примеры во входе — единственное намеренное различие серий; смена весов или параметров требует повторного исходного измерения.
4. Ученик разбирает хотя бы одну ошибку по уровням либо объясняет границы безошибочного малого набора.
5. Результаты фикстур не выданы за качество модели, а добавление примеров не названо дообучением.

Практика с моделью завершается после двух полных серий и их разбора. Отметка о незавершённой серии сохраняет честное состояние работы и не заменяет её завершения.

## Свой эксперимент

Составь две новые заявки, где формат легко соблюсти, а смысл перепутать: отрицание срочности, неизвестный напиток, отсутствующее количество или слишком большое число. До запуска напиши содержательный эталон. Не добавляй эти же заявки как примеры во вход. Сравни обе версии промпта и объясни результат.
