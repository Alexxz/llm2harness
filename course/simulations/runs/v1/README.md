# Симуляции методичек, v1

Публикационная копия: сведения о подключении и личные пути обезличены; исторические хеши не удостоверяют эту копию. Метод разработки преподавателя — `course/TEACHER_DEVELOPMENT.md`.
Тип свидетельства: `agent_pedagogy_simulation`. Это диалоги независимых агентных ролей на синтетических данных; они не измеряют обучение человека или качество реальной модели курса. Оценивание координатором не проводилось.

Проведены шесть сценариев с отдельными преподавателем и учеником и одна контрольная ветка со свежим учеником. Каждая ветка содержит исходный ответ, ровно три вмешательства с ответами ученика и новый вопрос на перенос без помощи преподавателя. Контроль использует три заранее заданные общие фразы.

Сохранено 76 записей исходных сообщений, включая точные начальные задания ролям. Все роли создавались с `fork_turns="none"`, без переопределения модели. Во время работы одновременно допускалось не более шести ролевых агентов. Преподаватели получали только назначенные методички, синтетические наблюдения и точные реплики ученика; личные карточки и вопросы на перенос им не передавались. Ученики получали только свою README, карточку, исходный вопрос, сообщения преподавателя и в конце вопрос на перенос.

[source-manifest.json](source-manifest.json) содержит полные исходные тексты и SHA256 двенадцати разрешённых документов. [integrity-check.json](integrity-check.json) фиксирует проверку структуры и совпадение исходных хешей с текущими файлами на момент завершения. Источники за время диалогов не изменились. Все 18 реплик преподавателей содержат от 177 до 199 слов по разделению пробелами.

Ограничения протокола сохранены в каждом случае. В частности, README доступна до исходного ответа, карточка задаёт заблуждение и условия его пересмотра, а модельный стек ролей общий. Преподавателю не сообщался исходный вопрос отдельно от ответа ученика: данные, которые ученик не повторил, могли сначала быть ему неизвестны. В случае schema-versus-meaning первая реплика ученика не содержала исходную заявку и JSON; преподаватель начал с другого явно синтетического примера. Это сохранено без исправления хода диалога.

Названия и содержимое контрольной ветки не скрыты в исходных журналах. Отдельный проверяющий должен оценить все случаи по зафиксированным критериям; координатор не присваивал баллы и не делал вывод об эффективности методичек.

Модели курса, установки, загрузки, обучение, Docker, реальные записи и внешние API в этих испытаниях не запускались. Роли использовали строго read-only чтение назначенной документации; прочие действия оставались обсуждением.
