# Повторы запросов и пределы работы

## Статус единой лаборатории

Маршрут этого урока после обновлённых 00–04 проработан в [LABORATORY_PLAN.md](LABORATORY_PLAN.md), но ещё не перенесён в рабочее поле. Ниже сохранён прежний технический маршрут; он не является готовым продолжением новой лаборатории.


Сначала прочитай [введение и первый шаг](INTRO.md): там объяснены смысл опыта, участники и конкретный текст для чтения. Блоки подготовки и опытов ниже предназначены для обычного Bash-терминала. В приглашении `ученик>` используй команды учебной консоли из введения и указаний преподавателя.

Для совместной работы открой [учебную консоль с преподавателем](../../course/TERMINAL_CLASSROOM.md): `./lab classroom start --lesson 13` из корня проекта. Промпты, явные запуски и советы этой сессии видны преподавателю; обычные команды других терминалов в журнал не попадают.


## Цель

Научиться выбирать реакцию на сбой: повторить запрос к модели, попросить исправить форму ответа, вернуть ошибку проверки или остановиться для выяснения результата действия. Повторение не меняет веса модели. Само слово «ошибка» не определяет, какой из этих путей подходит.

Идемпотентность относится к эффекту повторного действия: желаемое состояние после нескольких одинаковых вызовов совпадает с состоянием после одного. Ответы при этом могут различаться. Для HTTP это различие описано в [RFC 9110, раздел 9.2.2](https://www.rfc-editor.org/rfc/rfc9110.html#section-9.2.2). Для нашего `run_bash` свойство нужно устанавливать по самой операции, а не по названию инструмента.

## Перед началом

Работай из корня проекта. Нужны Python 3.12, jq и результаты занятий 09–12. Первые два опыта полностью автономны и не обращаются к модели, сети или контейнеру. Для третьего нужен подготовленный локальный сервер ядра из ресурсного плана курса. Его модель и настройки фиксируем в обоих запусках.

Создай каталог для наблюдений:

```bash
mkdir -p results/13
/usr/bin/python3 -m coursekit doctor
```

Файлы `fixtures/cases.json` — заданные учебные ситуации. Их вывод не является измерением качества языковой модели. Скрипт `retry_experiment.py` исследует решения программы курса; он не добавляет скрытые повторы в основной `ModelClient`, который делает один запрос.

## План занятия

На занятие отведено 75 минут: 10 минут на прогнозы, 20 на классификацию сбоев, 15 на исчерпание бюджета, 20 на опыт с моделью и 10 на разбор свидетельств. Подготовка весов и сервера выполняется заранее.

## Опыты

### Сначала выбери реакцию сам

Прочитай `fixtures/cases.json`. Не открывая поле `expected`, выпиши решения для шести случаев:

| Случай | Что известно | Что требуется различить |
| --- | --- | --- |
| A | Генерация недоступна временно; инструменты ещё не вызывались | Новый запрос к модели и повтор инструмента |
| B | Модель вернула оборванный JSON | Исправление формата и повтор HTTP-запроса без обратной связи |
| C | Проверка скрипта завершилась с ненулевым кодом | Исправление программы и повтор той же ошибочной проверки |
| D | Shell-вызов превысил время; неизвестно, была ли добавлена строка | Повтор действия и выяснение уже произошедшего эффекта |
| E | Политика отклонила путь | Исправление разрешённой задачи и обход запрета повторами |
| F | Чтение неизменяемой учебной заметки прервалось | Повтор чтения и повтор записи |

Затем запусти проверку стенда:

```bash
/usr/bin/python3 lessons/13-retries/retry_experiment.py --self-test
/usr/bin/python3 lessons/13-retries/retry_experiment.py --max-attempts 3 > results/13/three-attempts.json
jq '.decisions[] | {id, decision, attempts_used, max_attempts}' results/13/three-attempts.json
```

Ожидаемые решения при заданных входах: A — `retry_model`, B — `repair_json`, C — `repair_code`, D — `reconcile`, E — `stop_policy`, F — `retry_read`. Скрипт не ждёт реальных таймаутов и не выполняет описанные команды. Он выводит, какой следующий шаг разрешает учебная политика.

Для D придумай два возможных состояния мира: строка уже добавлена и строка ещё не добавлена. В обоих случаях наблюдение клиента одинаково — ответа нет. Поэтому одного повторного запуска для восстановления недостаточно. В нашем агенте действие с неизвестным эффектом требует остановки и сверки фактических артефактов.

### Измени только бюджет

Не меняй входные случаи. Уменьши число допустимых попыток:

```bash
/usr/bin/python3 lessons/13-retries/retry_experiment.py --max-attempts 1 > results/13/one-attempt.json
jq '.decisions[] | {id, decision}' results/13/one-attempt.json
```

Теперь A, B, C и F должны получить `stop_budget`: единственная попытка уже израсходована. D остаётся `reconcile`, E — `stop_policy`. Неопределённый побочный эффект требует выяснения даже тогда, когда новые запросы запрещены бюджетом. Сравни результаты с прогнозом. В учебном скрипте первая попытка входит в лимит; это не «ещё три повтора».

Теперь проследи настоящий цикл повторного вызова функции с заданным генератором. Он дважды выбрасывает синтетическое временное исключение и на третьем вызове возвращает заданный текст. Это проверка компонента повторов без HTTP и без языковой модели:

```bash
/usr/bin/python3 lessons/13-retries/retry_experiment.py --sequence --max-attempts 3 > results/13/sequence-three.json
/usr/bin/python3 lessons/13-retries/retry_experiment.py --sequence --max-attempts 1 > results/13/sequence-one.json
jq '{kind, status, calls, events}' results/13/sequence-three.json
jq '{kind, status, calls, events}' results/13/sequence-one.json
```

При лимите 3 функция вызывается трижды и получает `success`; при лимите 1 — один раз и получает `stop_budget`. Проследи в исходнике, что счётчик расходуется до обращения, поэтому исключения тоже входят в лимит. Эта маленькая обёртка не повторяет инструменты и не ловит произвольные исключения как временные. Обсуди, почему реальному транспорту дополнительно нужны таймаут каждого запроса, общий дедлайн и предел размера ответа.

### Дай те же случаи настоящей модели

Промпты содержат одинаковые ситуации и одинаковый формат ответа. В `variation.txt` добавлено только правило принятия решения. Меняется инструкция; модель, `seed`, температура, данные и лимит ответа остаются прежними.

```bash
/usr/bin/python3 -m coursekit complete --prompt-file lessons/13-retries/prompts/baseline.txt --endpoint http://127.0.0.1:8088 --max-tokens 384 --temperature 0 --seed 42 --output results/13/baseline.json
/usr/bin/python3 -m coursekit complete --prompt-file lessons/13-retries/prompts/variation.txt --endpoint http://127.0.0.1:8088 --max-tokens 384 --temperature 0 --seed 42 --output results/13/variation.json
jq -r '.text' results/13/baseline.json > results/13/baseline-answer.json
jq -r '.text' results/13/variation.json > results/13/variation-answer.json
/usr/bin/python3 -m coursekit check-json --schema lessons/13-retries/decision.schema.json --input results/13/variation-answer.json
/usr/bin/python3 lessons/13-retries/retry_experiment.py --score results/13/variation-answer.json
```

Проверка схемы доказывает форму ответа. Отдельная оценка сравнивает решения с явно заданным ключом. Если JSON не разбирается, сохрани сырой ответ; не выдавай ручное исправление за исходный результат модели. Сначала оцени оба ответа без грамматики. Ограниченную генерацию из занятия 06 можно добавить отдельным третьим опытом.

## Ожидаемые наблюдения

Проверка стенда воспроизводимо показывает разные реакции на разные причины сбоя и останавливает новые попытки при исчерпании бюджета. Успешный ответ модели может предложить эти же реакции, но исполнять политику должна программа. Если модель ошиблась в D, harness всё равно обязан запретить слепой повтор.

Одинаковый `seed` облегчает сравнение в одной конфигурации, но не гарантирует совпадение результатов между разными версиями движка или оборудования. Не делай вывод о качестве на основании одного улучшившегося ответа.

## Если результат отличается

Если `--self-test` не проходит, это ошибка учебного скрипта или изменённых фикстур; модель тут не участвует. Если оба промпта дают правильные решения, добавь новый случай с двусмысленным результатом, не ухудшая исходный пример искусственно. Если модель не соблюдает JSON, отметь отдельно ошибку формы и ошибку смысла. Для ошибочного кода проверка возвращает содержательную обратную связь; повтор неизменённого HTTP-запроса не передаёт её модели.

Плохой пароль, отсутствие доступа и отказ политики не становятся временным сбоем от большого числа повторов. Эти примеры обсуждаем на синтетических ситуациях; реальные учётные данные в занятии не используются.

## Что сохранить

Сохрани собственные прогнозы, два результата проверки бюджета, оба исходных ответа модели и таблицу: случай, причина, реакция, какой бюджет расходуется, возможен ли побочный эффект. Укажи версию весов и движка, дату запуска и параметры. Если опыт с моделью не выполнен, пометь его `not_run`.

## Критерии завершения

- Ты различаешь повтор запроса к модели, исправление JSON и исправление кода.
- Проверка стенда показывает `reconcile` для неизвестного эффекта записи и `stop_budget` для исчерпанных новых попыток.
- Ты можешь объяснить, почему таймаут после отправки не доказывает, что действие не произошло.
- Для настоящей модели сохранены исходные ответы и раздельные проверки формы и решений либо явно отмечено, что live-часть ещё не пройдена.
- Ты показываешь в исходнике, где расходуется попытка, и объясняешь, чего этот маленький скрипт ещё не реализует: сетевой backoff и гарантии дедупликации операций.

## Свой эксперимент

Добавь случай «прочитали заметку, затем другой процесс изменил её». Повтор чтения не создаёт запись, но может вернуть другое содержимое. Объясни различие между идемпотентностью, одинаковым ответом и согласованностью снимка данных. Предложи проверку версии заметки перед продолжением задачи.
