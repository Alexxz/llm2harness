# Урок 02. Контекст и явно передаваемая история

## Запуск

Из корня проекта в обычном Bash:

```bash
./lab classroom start --lesson 02 --split
```

Запуск сам проверяет подключение преподавателя и готовит зависимости этого урока до открытия класса. Необходимые публичные веса и локальная среда подготавливаются автоматически; первый запуск может занять время и потребовать несколько GB свободного места. Обучение не начинается при подготовке.

На машине должны быть Python 3.12 с зависимостями requirements.txt, tmux и заранее авторизованное [подключение преподавателя](../../course/TEACHER_RUNTIME.md). Для первой сборки ядра уроков 01–03 нужны git, cmake и C++; для урока 04 — модуль venv и доступ к публичным пакетам. Системные пакеты и вход в аккаунт устанавливаются пользователем. Ошибка подготовки останавливает запуск до создания учебной сессии; после устранения причины повтори ту же команду. Отчёт сохраняется в results/preparation/, отдельно от опытов ученика.


## Цель

Увидеть, откуда модель получает сведения для ответа. Сравнить один вопрос с фактом, без него и после замены факта. Затем самому составить второй запрос, включив настоящий результат первого.

Внутреннюю математику модели не разбираем. Меняем только переданный текст при прежних весах и настройках.

## Перед началом

Нужен пройденный урок 01. Сервер того же профиля запускается и проверяется автоматически. Отдельно подключать чат-API или инструменты не требуется. Подготовка и команда повторного запуска сервера описаны в [SETUP.md](SETUP.md).

В обычном терминале из папки курса:

```bash
./lab classroom start --lesson 02 --split
```

F2 — преподаватель, F3 — опыты, Ctrl+h — помощь, F4 — последний результат. F9 — песочница: F7 выбирает текст, F8 — параметры, F5 запускает запрос; можно редактировать и запускать многократно. Она не меняет основное задание.

Первое задание появляется сразу. show и load — локальные команды; после них не нужно ждать ответа преподавателя. Перед первым запросом готовая карточка объяснит run. Вопросы обсуждаются слева; копировать преподавателю весь вывод не требуется.

## План занятия

| Время | Что делаем |
|---|---|
| 0–10 минут | Первый ответ на короткий вход с именем кота. |
| 10–30 минут | Игра: убрать имя, заменить его; разобрать источник ответа. |
| 30–55 минут | Получить собственный первый выход и вручную собрать следующий вход. |
| 55–65 минут | Удалить собранную историю, сохранив последний вопрос. |
| 65–75 минут | Связать наблюдения и разобрать один новый случай. |

На 60 минут сокращается свободная игра; на 90 можно добавить свой факт в песочнице. Ручная сборка второго запроса сохраняется в любом варианте.

## Опыты

### 1. Факт в текущем входе

Исходный текст уже загружен:

```text
Имя кота: Плюш.
Вопрос: Как зовут кота?
Ответ:
```

Справа `show` показывает весь вход. После готовой подсказки `run` передаст его модели. В результате посмотри, какое имя появилось. Преподаватель укажет конкретную строку, откуда оно могло взяться; предварительный прогноз необязателен.

Готовые настройки: temperature=0, seed=42, max_tokens=24. Они не требуют нового изучения; для сравнений оставляем их одинаковыми.

### 2. Убираем факт и заменяем его

Когда преподаватель объяснит сравнение, `load variation` оставит:

```text
Вопрос: Как зовут кота?
Ответ:
```

После чтения сразу можно `run`, без промежуточного ожидания преподавателя. Модель может всё равно уверенно назвать имя. Проверь, был ли источник этого имени во входе. Не требуется добиться ответа «НЕИЗВЕСТНО» любой ценой.

Затем `load replace_fact` вернёт полный вход, заменив только Плюш на Бублик. После запроса сопоставь ответы при прежних параметрах. Преподаватель восстановит короткую таблицу из журнала; помнить предыдущие ответы по номерам не нужно.

Если хочется поиграть, в F9 попробуй своё вымышленное имя, убери строку или замени её. Это самостоятельные опыты с отдельной меткой в журнале. Песочница не меняет промпт основного задания.

### 3. Делаем историю из настоящего результата

До действия преподаватель объяснит механизм: старый ответ виден в окне и журнале, но ядро увидит его в следующем запросе только тогда, когда программа включит его в новый вход.

`load first_turn` подготовит начало:

```text
В сказочном лесу жил кот по имени
```

Выполни `run`. Это твой настоящий первый ход. В ответе модель может придумать имя и продолжить рассказ; сохраним весь полученный текст, включая обрыв.

Теперь соберём следующий запрос в большом редакторе:

1. Нажми **F10** — откроется текст учебного запроса.
2. В редакторе нажми **F6**. Программа возьмёт первый вход и полный настоящий ответ из журнала и добавит вопрос. Модель при этом не вызывается.
3. Прочитай собранный текст: найди прежний ответ и новый вопрос. Стрелками можно перемещать курсор и редактировать текст; Enter добавляет строку, Backspace/Delete удаляют символы.
4. **F5** сохраняет и закрывает редактор. **Esc** отменяет изменения. Набирать `::end` не нужно.
5. В терминале ученика выполни `show` для проверки, затем `run`.

Вставка сохраняет весь реальный ответ, включая пробелы, переносы и оборванные слова. Здесь историю явно добавляет программа по твоему нажатию F6. Само наличие старого ответа в журнале ещё не передаёт его модели.

В новом запросе найди первый ответ. Теперь модель получает его вместе с вопросом. Сопоставь второе продолжение с переданным рассказом. Даже если имя не извлечено, у нас есть проверяемая цепочка вход → выход → новый вход, в котором выход присутствует.

### 4. Оставляем только последний вопрос

После разбора `load variation` снова покажет только вопрос и начало ответа. Сравни этот запрос с только что собранным вторым входом, сохранив настройки. Удаляется вся ранняя история, а последний вопрос остаётся тем же.

Файл, окно и память человека сами не добавляют прошлые реплики в запрос. Если ответ без истории совпал с прежним, одного совпадения недостаточно, чтобы доказать память модели. Если не совпал — покажи конкретно, что было удалено.

## Ожидаемые наблюдения

Контекст — сведения текущего входа. Историю сохраняет и собирает программа; в ручном опыте ты явно составляешь текст, который она передаст. Модель может использовать переданный факт, ошибиться или сгенерировать неподтверждённое имя. Изменение входа не обновляет веса.

В raw completion надписи «Вопрос» и «Ответ» — обычные части текста. Они не дают отдельного чата, прав доступа или дополнительных процессов. Позднее программа будет автоматически хранить и упаковывать реплики; сейчас важно увидеть саму операцию сборки.

## Если результат отличается

- Без имени появился уверенный ответ: установи отсутствие источника во входе; это не доказательство памяти.
- Переданное имя не использовано: сохрани ответ и покажи расхождение, не меняя веса или параметры незаметно.
- После замены Плюш на Бублик ответ не изменился: проверь фактический model_request, затем разбери ошибку следования контексту.
- Первый рассказ оборван: перенеси его таким, как он получился. Не дописывай за модель.
- Второй вход не содержит полный первый выход: исправь конкретное место после объяснения. Само верное имя ещё не доказывает сборку истории.
- Запрос не прошёл: результата модели нет; сначала восстанови подготовку.

## Что сохранить

Стенд хранит точные входы, настройки, выходы и события в `results/classroom/ИДЕНТИФИКАТОР`. Второй вручную составленный вход тоже сохранится в состоянии сессии и запросе запуска. Показывать историю нужно по этим данным, а не только устному пересказу.

Твои заметки можно сохранить в `observations.md` через `write observations.md`, если преподаватель предварительно объяснил эту команду. Для каждого сравнения полезны три записи: какой факт был в переданном тексте; что модель написала; поддержан ли ответ входом.

## Критерии завершения

1. Есть собственные реальные ответы на baseline, variation и replace_fact при сопоставимых настройках.
2. Получен настоящий первый ход first_turn и второй запрос, содержащий его полный фактический выход.
3. Есть ответ на сокращённый второй вход с тем же последним вопросом и без ранней истории.
4. Ты можешь показать, какой текст получил сервер и откуда берётся поддержанный ответ.
5. После объяснения ты различаешь сохранение истории программой, включение истории в текущий вход и изменение весов.

Верные имена во всех запусках не обязательны. Важны честное сравнение и разбор наблюдений. Преподаватель явно скажет **«Урок 02 завершён»**. Закрытие окна через /exit — отдельное действие.

## Свой эксперимент

В F9 придумай нейтральный факт: имя кота, название вымышленной станции или цвет предмета. Сделай вход с фактом, без него и с заменой только факта. Сохрани настройки. Предложи, какой ответ был бы подтверждён входом, а какой останется догадкой.

Если интересно устройство автоматической сборки, [dialog.py](dialog.py) показывает один вариант рендера сообщений и включения сохранённого ответа. Это дополнительная техническая практика, а не обязательная Bash-цепочка перед наблюдением модели.
