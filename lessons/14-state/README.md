# Состояние задачи и возобновление агента

## Статус единой лаборатории

Маршрут этого урока после обновлённых 00–04 проработан в [LABORATORY_PLAN.md](LABORATORY_PLAN.md), но ещё не перенесён в рабочее поле. Ниже сохранён прежний технический маршрут; он не является готовым продолжением новой лаборатории.


Сначала прочитай [введение и первый шаг](INTRO.md): там объяснены смысл опыта, участники и конкретный текст для чтения. Блоки подготовки и опытов ниже предназначены для обычного Bash-терминала. В приглашении `ученик>` используй команды учебной консоли из введения и указаний преподавателя.

Для совместной работы открой [учебную консоль с преподавателем](../../course/TERMINAL_CLASSROOM.md): `./lab classroom start --lesson 14` из корня проекта. Промпты, явные запуски и советы этой сессии видны преподавателю; обычные команды других терминалов в журнал не попадают.


## Цель

Увидеть, что продолжение работы обеспечивают сохранённые данные harness и новый запрос к модели. Различить четыре вещи: файлы проекта, журнал событий, сохранённое состояние выполнения и текст, фактически переданный модели. Веса модели во всех опытах остаются прежними.

## Перед началом

Нужны результаты занятий 09 и 13, системный `/usr/bin/python3`, jq и локальный сервер той же модели. Проверка восстановления ниже автономна; опыт с вопросом пользователю требует настоящего обращения к модели. До подготовки весов live-часть остаётся `not_run`.

```bash
mkdir -p results/14/control results/14/workspace
/usr/bin/python3 -m coursekit doctor
```

`workspace` доступен инструментам агента. `control` хранит доверенные checkpoints, ответы пользователя и журналы; этот каталог не монтируется в контейнер. Указание текущей папки само по себе доступ не ограничивает: нужны проверки путей и граница исполнения из занятия 12.

## План занятия

75 минут: 10 на различение видов состояния, 15 на потерю контекста, 15 на заданные точки сбоя, 25 на вопрос и возобновление настоящего агента, 10 на разбор. Загрузки и запуск сервера подготовлены до занятия.

## Опыты

### Убери ровно один факт из входа

Прочитай два промпта. Во втором удалена только строка с меткой задачи. Вопрос и правило ответа одинаковы. История другого разговора автоматически в эти файлы не попадает.

```bash
/usr/bin/python3 -m coursekit complete --prompt-file lessons/14-state/prompts/baseline.txt --endpoint http://127.0.0.1:8088 --max-tokens 32 --temperature 0 --seed 42 --output results/14/control/context-full.json
/usr/bin/python3 -m coursekit complete --prompt-file lessons/14-state/prompts/variation.txt --endpoint http://127.0.0.1:8088 --max-tokens 32 --temperature 0 --seed 42 --output results/14/control/context-short.json
jq -r '.text' results/14/control/context-full.json
jq -r '.text' results/14/control/context-short.json
```

В полном входе ожидаем `MINT-472`; в сокращённом — `НЕТ_ДАННЫХ`. Если модель угадывает или придумывает значение, это ошибка ответа, а не признак доступа к прошлому процессу. Покажи в сохранённом запросе, была ли метка передана. Изучение фактически отправленного текста важнее правдоподобного объяснения модели о своей памяти.

Сокращение истории становится отдельным преобразованием данных. Для него нужны критерии: какие договорённости, результаты проверок и нерешённые вопросы обязаны сохраниться. Маленький пересказ не гарантирует сохранение нужного факта.

### Сравни заданные точки сбоя

В `fixtures/states.json` лежат условные учебные снимки. Это не настоящие checkpoints runtime. Их небольшая форма позволяет независимо разобрать решения до изучения полного файла состояния.

```bash
/usr/bin/python3 lessons/14-state/checkpoint_experiment.py --self-test
/usr/bin/python3 lessons/14-state/checkpoint_experiment.py > results/14/control/crash-decisions.json
/usr/bin/python3 lessons/14-state/checkpoint_experiment.py --show-naive-replay > results/14/control/naive-replay.json
```

Прогнозируй решение до чтения `expected`:

- После записанного результата чтения допустим следующий запрос модели; само чтение не нужно слепо воспроизводить из журнала.
- Завершённый запуск возвращает сохранённый результат без нового запроса.
- Ожидание пользователя сохраняет паузу до получения ответа.
- Незавершённое действие с неизвестным эффектом получает `outcome_unknown`. Восстановление не исполняет его заново.
- Исчерпанный бюджет не обнуляется после перезапуска процесса.
- Неподдерживаемый формат состояния отклоняется, а не интерпретируется догадкой.

Последняя команда показывает только счётчик в памяти: наивное повторение добавило бы эффект второй раз. Она не записывает файлы и не исполняет shell. Установка `pending` до действия и атомарное сохранение после него сужают окно неопределённости, но не превращают произвольный инструмент в exactly-once. Примитив атомарной замены файла описан в [документации Python](https://docs.python.org/3.12/library/os.html#os.replace); гарантии целой операции определяет весь протокол записи и восстановления.

### Поставь настоящего агента на паузу

`prompts/ask-name.txt` просит сначала уточнить имя будущего файла. Исходный бюджет — шесть шагов на весь запуск, включая продолжение. Запускаем с реальной моделью:

```bash
/usr/bin/python3 -m coursekit agent --task-file lessons/14-state/prompts/ask-name.txt --workspace results/14/workspace --endpoint http://127.0.0.1:8088 --max-steps 6 --tools read_file,write_file --state results/14/control/state.json > results/14/control/first.json
jq '{status, answer, state_path}' results/14/control/first.json
```

Ожидаем `status: waiting_for_user` и вопрос в `answer`. В трассе есть `action_proposed` с действием `ask_user`, затем `waiting_for_user`. Это пауза, а не выполненная задача. Если агент сразу завершился или исчерпал попытки исправить JSON, сохрани результат и разбери нарушение контракта; не подменяй его удачной фикстурой.

Изучи доверенный checkpoint:

```bash
jq '{schema_version, run_id, status, steps, requests, config, pending}' results/14/control/state.json
```

Имя файла выбери сам. Для воспроизводимого примера используем `session-note.txt`:

```bash
printf '%s\n' 'Имя файла: session-note.txt. Содержимое: Сессия продолжена.' > results/14/control/answer.txt
/usr/bin/python3 -m coursekit agent --task-file lessons/14-state/prompts/ask-name.txt --workspace results/14/workspace --endpoint http://127.0.0.1:8088 --max-steps 6 --tools read_file,write_file --resume results/14/control/state.json --answer-file results/14/control/answer.txt > results/14/control/resumed.json
jq '{status, answer, steps}' results/14/control/resumed.json
```

Проверь файл собственным чтением из назначенного workspace, затем сопоставь действие записи и чтения с `tool_result` в трассе. После продолжения счётчики не начинают отсчёт с нуля. Новое сообщение пользователя добавлено в историю, а модель получает заново построенный текстовый вход.

Сохрани в карточке запуска идентификатор и контрольную сумму весов, версию движка и все аргументы. При возобновлении harness связывает состояние с endpoint и настройками: нельзя незаметно увеличить бюджет или подключить новые инструменты. Он не определяет замену весов за тем же URL. Неизменность модели проверяет ученик по карточке и конфигурации сервера; при смене весов сравнение становится отдельным опытом. Новая задача также отличается от продолжения старой.

### Проверь границу доверенных данных

Объясни до запуска, почему следующий путь для состояния должен быть отклонён:

```bash
/usr/bin/python3 -m coursekit agent --task-file lessons/14-state/prompts/ask-name.txt --workspace results/14/workspace --endpoint http://127.0.0.1:8088 --max-steps 6 --tools read_file,write_file --state results/14/workspace/state.json
```

Ожидается отказ до запроса модели: агент не должен редактировать собственный доверенный checkpoint через доступный ему workspace. Наличие JSON на диске ещё не делает его достоверным. Не перемещай рабочий checkpoint внутрь workspace для удобства.

## Ожидаемые наблюдения

Сокращение входного текста может удалить нужный факт. Сохранённый checkpoint позволяет harness восстановить разговор и счётчики, но не добавляет информацию в модель иначе как через следующий запрос. В ответе пользователя появляется новый источник данных, который можно показать в истории.

Проверка стенда различает сохранённый результат и неизвестный эффект незавершённого действия. Журнал полезен для объяснения событий, однако произвольное повторное проигрывание всех записей способно повторить побочные эффекты.

## Если результат отличается

Если нет `waiting_for_user`, сначала проверь исходный ответ модели и ошибки разбора действия. Если budget исчерпан, resume не даёт новых бесплатных попыток: это отдельный исход опыта, а не повод вручную исправлять счётчики. Если runtime не видит сервер, это проблема транспорта, а не восстановления памяти.

При `outcome_unknown` не удаляй `pending`, чтобы «продолжить». Сначала сопоставь артефакт, журнал и действие; для произвольного shell нельзя вывести успех только из ожидаемого имени файла. Возобновление другого workspace или с другой конфигурацией должно быть отклонено.

## Что сохранить

Сохрани два входа и ответа опыта с контекстом, таблицу решений по точкам сбоя, `first.json`, ответ пользователя, `resumed.json` и доверенный checkpoint. Составь схему: файл/событие → кто создаёт → кто имеет право менять → попадает ли в следующий запрос модели.

## Критерии завершения

- Ты показываешь факт, потерянный при сокращении входа, и отличаешь его от изменения весов.
- Проверка заданных снимков останавливает восстановление при неизвестном эффекте и не сбрасывает бюджет.
- В реальном запуске сохранены вопрос, ответ человека и продолжение либо live-часть честно отмечена `not_run`.
- Доверенное состояние находится вне workspace; попытка поместить его внутрь отвергается.
- Ты объясняешь, почему журнал событий и точка безопасного продолжения — разные вещи.

## Свой эксперимент

Для опыта с контекстом придумай сокращённую сводку, сохраняющую метку, и другую, теряющую её. Данные и вопрос оставь прежними. Сравни точность ответа, длину входа и возможность восстановить источник факта. Не оценивай хорошую сводку только по её краткости.
