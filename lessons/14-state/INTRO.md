# Урок 14. Что именно сохраняет «память» агента

Мы уже умеем выполнять ограниченный цикл и разбирать причины остановки. Теперь исследуем продолжение работы: какие данные должна сохранить программа, чтобы после паузы не потерять задачу и не повторить уже выполненное действие.

Разделим файлы проекта, журнал событий, состояние выполнения и текст следующего запроса к модели. Сохранённое состояние содержит данные для программы курса; модель узнаёт нужные сведения, когда они включены в её очередной вход. Это не изменение её весов.

Перед тобой учебная консоль со своим журналом. Преподаватель наблюдает её события в ходе нашего разговора. Учебная сессия и задача, которую позже выполняет агент, — два разных состояния: открыть консоль недостаточно, чтобы восстановить любую старую задачу.

Заданные примеры восстановления можно разобрать без модели. Для опыта с настоящим вопросом пользователю и продолжением нужен подготовленный сервер. Настоящие состояния и счётчики берём из результатов запуска; вручную сочинённый файл не выдаём за сохранённую работу агента.

## Первый шаг

Начнём с маленького видимого входа, до сложных файлов состояния. В приглашении `ученик>` введи:

```text
show
```

Ты увидишь текст с записью задачи, её меткой и вопросом. `show` только показывает подготовленный вход, не вызывает модель и не восстанавливает прошлый разговор. Прочитай строки между «В записи задачи» и «Вопрос», затем сам вопрос.

Своими словами назови, какую часть этого видимого текста понадобится передать модели для ответа. Это разбор источника данных; предсказывать работу незнакомого механизма восстановления сейчас не требуется.

 Ответы и вопросы пиши в канале преподавателя. Преподаватель сам прочитает результаты опытов в журнале.
