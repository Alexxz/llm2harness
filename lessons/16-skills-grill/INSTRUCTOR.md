# Преподавание навыков и интервью GrillMe

## Статус единой лаборатории

Маршрут этого урока после обновлённых 00–04 проработан в [LABORATORY_PLAN.md](LABORATORY_PLAN.md), но ещё не перенесён в рабочее поле. Ниже сохранён прежний технический маршрут; он не является готовым продолжением новой лаборатории.


Перед занятием прочитайте [руководство преподавателя](../../course/TEACHER_GUIDE.md): оно задаёт порядок подсказок, возврата к исходной ошибке и проверки самостоятельного переноса.

## Вход в занятие до прогнозов

Прочитайте с учеником [введение](INTRO.md). До прогнозов качества интервью попросите ученика своими словами назвать результат обсуждения и недостающие личные решения. Разведите разговор с преподавателем в канале преподавателя и будущий ответ учебному агенту через `answer`. Проверьте, что показ задания не начал интервью и не создал игру.

Если ученик не понимает, зачем вводить команду или какой текст читать, вернитесь к её назначению, точному объекту и ожидаемому виду результата. Продолжайте после его объяснения своими словами, а не после одного «готово».

## Подготовка преподавателя

До занятия проверь endpoint, версию модели, работу ask_user и возобновления. Ученик должен иметь готовые правила состояния из занятия 14. Прочитай skills/grill-me.md и rubric.json. Не подготавливай за ученика решения по игре: именно его ответы должны влиять на последующий раунд.

Синтетические fixtures служат для разбора состояний без модели. Они не подменяют настоящий диалог и не служат доказательством эффективности навыка.

## План на 75 минут

| Минуты | Работа преподавателя |
| --- | --- |
| 0–10 | Попросить предсказать различия. Показать место подключения инструкции |
| 10–25 | Контрольный запуск. Не подсказывать модели правильный формат интервью |
| 25–45 | Навык включён. Разобрать один независимый и один зависимый вопрос |
| 45–60 | Ученик отвечает, harness возобновляет сессию |
| 60–70 | Ученик находит запрос, ask_user и статус ожидания в трассе |
| 70–75 | Записать вывод и нерешённые требования |

Для 60 минут оставь по одному запуску каждой конфигурации и один ответ человека. Для 90 минут добавь второй короткий проект и повтор сравнения. Не ускоряй занятие за счёт придуманного результата модели.

## Вопросы и ответы преподавателю

1. Изменились ли веса после подключения навыка? Нет. Изменился текст, который модель получила в текущем запросе.
2. Почему одинаковая модель может задавать вопросы и без навыка? Поведение уже частично усвоено во время её обучения; дополнительная инструкция направляет его, но не создаёт с нуля.
3. Кто останавливает выполнение, пока человек отвечает? Harness обрабатывает ask_user, сохраняет состояние и возвращает waiting_for_user.
4. Почему finish с вопросами — ошибка для интервью? Содержимое может быть вопросами, но протокол объявляет задачу завершённой и не сохраняет корректный ожидающий ход.
5. Как определить готовый фронт? Для каждого вопроса перечислить необходимые решения; все они должны быть уже приняты до начала раунда.
6. Может ли текст навыка гарантировать запрет записи файлов? Нет. Эту границу обеспечивает ограничение инструментов; в опыте запись не разрешена.

## Типичные заблуждения

«Навык — маленькая дополнительная модель». Покажи чтение файла и изменившийся запрос без обучения.

«Любое уточнение — уже GrillMe». Сравни вопросы с явной зависимостью: нельзя выбирать параметр режима, который ещё не согласован.

«Если модель красиво резюмировала, игра уже готова». Попроси показать файлы и результаты выполнения: в этом занятии их ещё не должно быть.

«Раз навык подключён, ответ обязательно лучше». Ученик должен иметь право увидеть одинаковое или худшее поведение. Оцениваем по рубрике и нескольким задачам, а не по впечатлению.

## Когда вмешиваться

Если модель повторяет уже решённое, предложи ученику найти свой предыдущий ответ в истории и сформулировать точную обратную связь. Если за три полезных раунда договориться не удалось, сохрани опыт как неуспешный, выясни причину и остановись по бюджету. Не заменяй модель внешним Codex, который незаметно завершит интервью.

Если агент получил полномочия записи или исполнения, исправь конфигурацию до повторного опыта. Повторение старой сессии с расширенными правами не является тем же экспериментом.

## Разбор без модели

Для fixtures/interview-rounds.json ожидается:

- waiting-round — корректная пауза, если вопросы действительно составляют готовый фронт.
- finished-with-questions — ошибка состояния: вопросы отправлены как завершение.
- continued-without-answer — преждевременное продолжение, решение пользователя выдумано.

Сначала ученик объясняет смысл, затем открывает эти ответы.

## Дополнительный опыт

Пусть ученик предложит изменение навыка, которое уменьшает число вопросов, но сохраняет зависимости и подтверждение общего понимания. Сравните две отдельные сессии и число необоснованных предположений. Изменение количества вопросов само по себе не является улучшением.


## Совместное наблюдение в терминале

Используйте [общий порядок совместного занятия](../../course/TERMINAL_CLASSROOM.md). Ученик открывает `./lab classroom start --lesson 16`. Преподаватель находит сессию через `./lab classroom list`, читает события через `observe SESSION --json` и просит прогноз до первого запуска.

Для этого этапа исходный набор компонентов: `./lab classroom permit SESSION --capabilities doctor,complete,agent,skill`. После проверки подготовки преподаватель выполняет `./lab classroom resume SESSION`. На разборе результата он использует `pause`, для прерывания активного опыта — `stop` и проверяет фактическое подтверждение.

Советы передавайте через `./lab classroom advise SESSION --message 'Текст следующего вопроса или опыта'`. Ученик отвечает и меняет вход самостоятельно. Дополнительные программы из методички, не подключённые к диспетчеру, обсуждайте отдельно: открытая консоль сама по себе не даёт наблюдение и остановку всех процессов ноутбука.
