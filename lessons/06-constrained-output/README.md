# Ограничение формата ответа при генерации

## Статус единой лаборатории

Маршрут этого урока после обновлённых 00–04 проработан в [LABORATORY_PLAN.md](LABORATORY_PLAN.md), но ещё не перенесён в рабочее поле. Ниже сохранён прежний технический маршрут; он не является готовым продолжением новой лаборатории.


Начни с [введения в урок](INTRO.md): оно объясняет новый механизм, роль консоли и первое действие до выполнения команд из подробного маршрута ниже.

В занятии 05 менялись обучаемые параметры. Здесь веса остаются теми же, а движок генерации получает JSON Schema и ограничивает допустимую форму ответа. Проверяем, что это даёт и чего не обеспечивает.

Для совместной работы открой [учебную консоль с преподавателем](../../course/TERMINAL_CLASSROOM.md): `./lab classroom start --lesson 06` из корня проекта. Промпты, явные запуски и советы этой сессии видны преподавателю; обычные команды других терминалов в журнал не попадают.


## Цель

Отличить просьбу о JSON, проверку готового ответа и ограничение генерации. Показать на одном запросе, почему правильный по схеме объект всё ещё может выражать неправильное действие.

## Перед началом

Нужны общий стенд, подготовленный сервер llama.cpp на `127.0.0.1:8088` и та же версия весов для всех запусков этого занятия. Версию сервера и профиль модели сохрани в журнале. Адаптер из занятия 05 не подключается: мы сравниваем два режима движка при одинаковых весах.

Раздел с заданными JSON выполняется без модели. Полная приёмка также требует настоящих запросов. Для команд извлечения сгенерированного текста используется знакомый тебе `jq`.

## Опыты

### Сначала проверь два независимых вопроса

Открой `command.schema.json`, `fixtures/expected.json` и три синтетических входа. Они заданы автором для проверки стенда, а не получены от модели.

```bash
./lab check-json --schema lessons/06-constrained-output/command.schema.json --input lessons/06-constrained-output/fixtures/synthetic-valid.json
./lab check-json --schema lessons/06-constrained-output/command.schema.json --input lessons/06-constrained-output/fixtures/synthetic-wrong-meaning.json
/usr/bin/python3 lessons/06-constrained-output/check_semantics.py --input lessons/06-constrained-output/fixtures/synthetic-valid.json
/usr/bin/python3 lessons/06-constrained-output/check_semantics.py --input lessons/06-constrained-output/fixtures/synthetic-wrong-meaning.json
```

Первые две команды должны пройти проверку схемы. Последняя должна завершиться с ненулевым кодом: задан другой файл. Это ожидаемый отрицательный опыт, а не поломка стенда.

```bash
./lab check-json --schema lessons/06-constrained-output/command.schema.json --input lessons/06-constrained-output/fixtures/synthetic-invalid.json
```

Здесь ожидается отказ по форме. Сформулируй различие между «можно разобрать как JSON», «соответствует контракту» и «правильно передаёт запрос».

### Один промпт без схемы и со схемой

```bash
./lab complete --prompt-file lessons/06-constrained-output/prompts/baseline.txt --endpoint http://127.0.0.1:8088 --max-tokens 128 --temperature 0 --seed 42 --output work/schema-free.json
./lab complete --prompt-file lessons/06-constrained-output/prompts/baseline.txt --endpoint http://127.0.0.1:8088 --max-tokens 128 --temperature 0 --seed 42 --schema lessons/06-constrained-output/command.schema.json --output work/schema-constrained.json
```

Между этими двумя командами меняется только передача схемы движку. Сам промпт, модель и параметры одинаковые. Отчёт `complete` содержит сгенерированный `text` и служебные сведения. Выдели именно текст ответа:

```bash
jq -r '.text' work/schema-free.json > work/schema-free-output.json
jq -r '.text' work/schema-constrained.json > work/schema-constrained-output.json
./lab check-json --schema lessons/06-constrained-output/command.schema.json --input work/schema-constrained-output.json
/usr/bin/python3 lessons/06-constrained-output/check_semantics.py --input work/schema-constrained-output.json
```

Сохрани и отказ, если он возник. Форматирование JSON может различаться; порядок ключей и пробелы не меняют смысл. Сообщение об ошибке сервера, неполный ответ или несовместимая схема не являются успешным структурированным ответом.

Повтори пару для `prompts/variation.txt`: это тот же запрос с просьбой объяснить выбор. Не смешивай эффект изменения промпта с эффектом схемы: для каждого промпта нужна собственная пара запусков.

### Измени разрешённые действия

Исследуй `finish-only.schema.json`. Она допускает только завершение, хотя запрос просит прочитать файл. Предскажи результат, затем выполни:

```bash
./lab complete --prompt-file lessons/06-constrained-output/prompts/baseline.txt --endpoint http://127.0.0.1:8088 --max-tokens 128 --temperature 0 --seed 42 --schema lessons/06-constrained-output/finish-only.schema.json --output work/schema-wrong-contract.json
```

Если движок успешно завершил генерацию по этой схеме, формальный контракт может быть соблюдён, а задача чтения всё равно не выражена. Если генерация или сервер отказались, сохрани отказ и объясни конфликт. Правильность задания схемы — ответственность программы вокруг модели.

## Ожидаемые наблюдения

На синтетических входах форма и смысл разделяются воспроизводимо. В настоящих запросах движок ограничивает форму по поддерживаемой схеме, а качество переноса имени файла всё равно требует проверки. Модель без ограничения тоже может сразу дать правильный JSON; это не делает два механизма одинаковыми.

Схема не изменяет веса и не выполняет действие. После выключения схемы следующий независимый запрос снова использует обычный режим генерации. Успех этого опыта не доказывает, что любые схемы или любые движки имеют одинаковые возможности.

## Если результат отличается

- Сервер не поддерживает поле схемы или конкретную конструкцию: проверь версию и ответ API, используй поддерживаемую простую схему. Не называй обычную валидацию ограничением генерации.
- Ответ оборван лимитом: проверь служебные сведения и сохранённый текст; неполный JSON считается неуспехом запроса.
- Схема проходит, а семантическая проверка нет: разбери неправильный path/action, не «улучшай» оценку удалением этой проверки.
- Без схемы уже всё верно: попробуй вариацию с пояснением и дополнительные заранее выбранные запросы, сохраняя все исходы. Не обещай найти ошибку в каждом запуске.

## Что сохранить

Сохрани пары запросов и ответов, версию модели и сервера, обе схемы, результаты проверок формы и смысла и своё объяснение границы гарантий. Заданные фикстуры храни отдельно от настоящих ответов.

## Критерии завершения

- Ты показал JSON, правильный по схеме и неправильный по задаче.
- Настоящая пара отличается только передачей схемы и имеет сохранённые входы/выходы.
- Ты отличаешь изменение промпта, изменение весов, ограничение генерации и проверку готового результата.
- Отказы и незавершённая генерация не засчитаны как успешный ответ по схеме.

## Свой эксперимент

Предложи запрос, где формат остаётся правильным, но ошибиться легко в содержимом: разные имена файлов, кавычки в строке или переносы строк. Заранее подготовь ожидаемое действие и отдельную проверку смысла.
