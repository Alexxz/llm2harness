# Урок 06. Ограничиваем форму во время генерации

Мы уже просили JSON текстом, проверяли готовый ответ и меняли параметры через обучение. Сейчас подключим ещё один механизм: программа генерации получает описание допустимой формы и ограничивает продолжение во время запроса.

Описание полей, типов и допустимых вариантов называется схемой. Проверить результат по схеме после ответа и использовать её при получении ответа — разные операции. Сегодня сравним один запрос без ограничения и с ограничением при тех же весах и настройках.

Форма и задача всё равно проверяются отдельно. Схема может разрешать строковое имя файла, но разрешённая строка ещё не гарантирует, что модель извлекла нужное имя из текущей просьбы. JSON с предложением действия также ничего сам не исполняет.

Ты находишься в учебной консоли. Она показывает входы, ведёт журнал и запускает разрешённые запросы к отдельному серверу модели. Преподаватель обсуждает события в чате. Для задания схемы предусмотрена отдельная настройка консоли; её смысл и точный файл разберём перед включением. Адаптер прошлого урока в это сравнение не подмешиваем.

Для живой пары нужны подготовленные веса, работающий сервер llama.cpp с поддержкой выбранной схемы и один зафиксированный профиль. Без них можно исследовать заданные JSON, но нельзя объявлять успешным запрос с ограничением генерации. Ошибка сервера и оборванный ответ сохраняются как отдельные исходы.

## Первое действие

Сначала прочитаем запрос, который позже отправим в двух режимах. Команда `show` печатает его без вызова модели:

```text
show
```

Прочитай правила действий и строку «Запрос». Отметь, что относится к форме будущего ответа, а что является содержанием самой задачи. Сейчас мы смотрим на текст входа; схему этой командой не подключали.

Расскажи преподавателю в чате, как ты различил эти две части. Это поможет выбрать независимые проверки до запуска сравнения. Ответы и вопросы пиши в канале преподавателя. Преподаватель сам прочитает результаты опытов в журнале.

Введение можно повторить через `lesson`. README описывает последующее включение схемы, проверку результатов и опыт с конфликтующим ограничением.
