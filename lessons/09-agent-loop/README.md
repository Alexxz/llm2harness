# Ограниченный цикл агента

## Статус единой лаборатории

Маршрут этого урока после обновлённых 00–04 проработан в [LABORATORY_PLAN.md](LABORATORY_PLAN.md), но ещё не перенесён в рабочее поле. Ниже сохранён прежний технический маршрут; он не является готовым продолжением новой лаборатории.


Начни с [введения в урок](INTRO.md): оно объясняет новый механизм, роль консоли и первое действие до выполнения команд из подробного маршрута ниже.

В предыдущем занятии ты сам связывал запрос, действие и результат. Теперь это делает программа: модель выбирает одно действие, harness проверяет его, инструмент возвращает наблюдение, затем программа формирует следующий вход. Ты исследуешь готовый цикл, его журнал и условие остановки.

Для совместной работы открой [учебную консоль с преподавателем](../../course/TERMINAL_CLASSROOM.md): `./lab classroom start --lesson 09` из корня проекта. Промпты, явные запуски и советы этой сессии видны преподавателю; обычные команды других терминалов в журнал не попадают.


## Цель

Получить небольшой артефакт через настоящий автономный запуск и показать, какие действия совершила модель, а какие — программа. Отдельно проверить, что ограничение числа шагов действует независимо от желания модели продолжать.

## Перед началом

Заверши занятие 08 и подготовь сервер модели на `http://127.0.0.1:8088`. Работай из корня проекта. Для основного опыта нужны только чтение и запись файлов внутри специально созданного рабочего каталога. Команды shell агенту здесь не требуются; исходный набор инструментов стенда ограничен `read_file`, `write_file` и управляющими действиями завершения или вопроса человеку.

Прочитай `coursekit/agent.py` и `coursekit/policy.py` вместе с преподавателем. Найди цикл, место генерации, проверку действия, возврат наблюдения и расход бюджета. Исполнение одного шага и чтение файла — обычный код Python, который можно проследить. Это новый компонент вокруг тех же весов модели.

Состояние и трасса хранятся вне каталога агента: агент не должен редактировать свидетельства собственной работы. Не используй каталог с личными или рабочими файлами. Готовый подготовщик создаёт только новый синтетический каталог внутри `results` и отказывается затирать предыдущий опыт.

```bash
/usr/bin/python3 -m coursekit doctor
/usr/bin/python3 -m coursekit prompt 09 baseline
```

## План занятия

| Минуты | Работа |
|---|---|
| 0–10 | Сопоставь ручной цикл прошлого занятия с кодом harness. |
| 10–25 | Предскажи последовательность действий и подготовь отдельный рабочий каталог. |
| 25–40 | Выполни настоящий автономный запуск, проверь артефакт независимо. |
| 40–55 | Повтори с бюджетом в один шаг. |
| 55–70 | Измени одно поле исходных данных и повтори полный запуск. |
| 70–80 | Исследуй отсутствие файла и запиши собственный критерий остановки. |

## Опыты

### Полный цикл

В [задаче](prompts/baseline.txt) нет содержимого `stock.json`. Агенту требуется прочитать исходные данные, вычислить два остатка, записать `report.json`, прочитать записанный результат и завершить работу. Сначала предположи, сколько запросов к модели потребуется и кто создаст файл.

```bash
/usr/bin/python3 lessons/09-agent-loop/prepare_workspace.py --workspace results/lesson09-baseline
/usr/bin/python3 -m coursekit agent --task-file lessons/09-agent-loop/prompts/baseline.txt --workspace results/lesson09-baseline --endpoint http://127.0.0.1:8088 --max-steps 6 --max-tokens 512 --tools read_file,write_file --state results/lesson09-baseline-state.json > results/lesson09-baseline-run.json
/usr/bin/python3 lessons/09-agent-loop/check_report.py --workspace results/lesson09-baseline
```

Ожидаемый артефакт — JSON с двумя целыми полями: `physical=159`, `available=144`. Проверяющий код пересчитывает результат из фактического `stock.json`; фраза агента «готово» не используется как доказательство правильности.

Открой `lesson09-baseline-run.json`. Найди предложения действий, решения политики, фактические результаты чтения и записи, следующий вход модели и причину завершения. Для каждого перехода покажи связь:

```text
модель предложила read_file → программа разрешила → программа прочитала
наблюдение вошло в следующий запрос → модель предложила write_file
программа записала → модель получила результат → последующая проверка → finish
```

Названия и подробные поля событий смотри в реальном журнале. Последовательность может отличаться от рисунка: дополнительные попытки, ошибки JSON и вопросы человеку тоже являются наблюдаемым поведением. Нужны проверенный результат и понятная трасса; совпадение формулировок не требуется.

### Бюджет в один шаг

Создай новый каталог с теми же синтетическими данными. Единственное исследуемое изменение — `--max-steps 1`; [вариант задачи](prompts/variation.txt) побайтно совпадает с исходным.

```bash
/usr/bin/python3 lessons/09-agent-loop/prepare_workspace.py --workspace results/lesson09-one-step
/usr/bin/python3 -m coursekit agent --task-file lessons/09-agent-loop/prompts/variation.txt --workspace results/lesson09-one-step --endpoint http://127.0.0.1:8088 --max-steps 1 --max-tokens 512 --tools read_file,write_file --state results/lesson09-one-step-state.json > results/lesson09-one-step-run.json
```

Открой статус, число шагов и события. После одного расходованного шага harness не должен делать второй запрос к модели. Исходная задача требует нескольких действий, поэтому полный проверенный результат за этот бюджет не ожидается.

Если модель первым ответом выдаст `finish`, программа может завершиться до исчерпания бюджета. Такой случай тоже не подтверждает выполнение задачи: проверь наличие и содержимое артефакта. Если появится неподтверждённое «успешно», отдели решение модели от фактической приёмки.

```bash
/usr/bin/python3 lessons/09-agent-loop/check_report.py --workspace results/lesson09-one-step
```

Отсутствующий отчёт даст код 1. Здесь это ожидаемый результат эксперимента с недостаточным бюджетом, а не сбой проверяющей программы. Запиши отдельно: «ограничение выполнено» и «прикладная задача не выполнена».

### Новые данные при том же harness

Поменяй только резерв: вместо 15 используй 24. Текст задачи, версия модели и бюджет остаются прежними. Новый каталог нужен, чтобы старый отчёт не притворился результатом нового запуска.

```bash
/usr/bin/python3 lessons/09-agent-loop/prepare_workspace.py --workspace results/lesson09-reserve24 --reserved 24
/usr/bin/python3 -m coursekit agent --task-file lessons/09-agent-loop/prompts/baseline.txt --workspace results/lesson09-reserve24 --endpoint http://127.0.0.1:8088 --max-steps 6 --max-tokens 512 --tools read_file,write_file --state results/lesson09-reserve24-state.json > results/lesson09-reserve24-run.json
/usr/bin/python3 lessons/09-agent-loop/check_report.py --workspace results/lesson09-reserve24
```

Физический остаток должен остаться 159, доступный — стать 135. В трассе найди именно те данные чтения, которые отличают этот опыт от исходного. Присутствие нового значения в запросе важнее сходства объяснения модели.

### Ошибка чтения

Это опыт до 90 минут либо домашнее продолжение. Подготовщик создаст пустой рабочий каталог, не подделывая результат инструмента:

```bash
/usr/bin/python3 lessons/09-agent-loop/prepare_workspace.py --workspace results/lesson09-missing --missing-stock
/usr/bin/python3 -m coursekit agent --task-file lessons/09-agent-loop/prompts/baseline.txt --workspace results/lesson09-missing --endpoint http://127.0.0.1:8088 --max-steps 6 --max-tokens 512 --tools read_file,write_file --state results/lesson09-missing-state.json > results/lesson09-missing-run.json
/usr/bin/python3 lessons/09-agent-loop/check_report.py --workspace results/lesson09-missing --expect-missing
```

Проверь фактическую ошибку инструмента и следующий вход модели. Корректное прикладное поведение — завершить задачу с объяснением недостатка данных без выдуманного отчёта. Если агент повторяет чтение, бюджет всё равно обязан ограничить цикл. Это два разных критерия: разумная реакция модели и техническая остановка harness.

## Ожидаемые наблюдения

- Последовательность действий возникает из настоящих ответов модели, а исполнение и политика находятся в обычной программе.
- При успехе появляется проверяемый файл, которого до запуска не было.
- Каждый результат инструмента попадает в последующий вход явно. Веса не меняются между шагами.
- Бюджет ограничивает число обращений даже при неверном JSON, повторе чтения или незавершённой задаче.
- Заявление о завершении, техническая остановка и успешная проверка артефакта — три разные вещи.

## Если результат отличается

Если рабочий каталог уже не пуст, выбери новое имя. Не удаляй свидетельства предыдущего запуска и не запускай сравнение поверх старого отчёта.

Если агент нарушает контракт действия, проверь события разбора и возвращаемую ошибку. Не меняй модель, бюджет и промпт одновременно. Разрешается один новый опыт с более ясной формулировкой контракта, после которого сравнение начинается заново с зафиксированными настройками.

Если заявлено `finish`, но проверка артефакта не проходит, основная практика пока не принята. Сохрани неуспех, разберите с преподавателем данные и контракт. Если выбранная модель не осиливает задачу в установленном бюджете, переход на более подходящую версию фиксируется как новая конфигурация; старые неудачи не удаляются.

Если сеть или сервер недоступны, это ошибка получения ответа модели. Увеличение числа прикладных шагов не исправляет доступ к серверу. Подробную классификацию ошибок и повторов исследуем в занятии 13.

## Что сохранить

Сохрани исходный рабочий каталог каждого опыта, задачу, конфигурацию модели, JSON результата со всеми событиями, отдельный файл состояния и вывод независимой проверки. Не помещай журналы внутрь рабочего каталога, доступного агенту.

Составь таблицу из четырёх колонок: опыт, число шагов, причина остановки, результат независимой проверки. Заданный бюджет и фактически потраченные шаги записываются отдельно.

## Критерии завершения

1. Настоящий автономный запуск создал правильный `report.json`, который проходит независимую проверку.
2. Ученик связал хотя бы один результат инструмента с последующим входом модели.
3. Контроль с одним шагом действительно не сделал больше одного запроса; неполный результат не назван успехом задачи.
4. При изменении резерва получен и проверен новый доступный остаток либо зафиксирована конкретная неудача новой конфигурации.
5. Ученик указывает, где находится цикл, кто исполняет действие и кто принял решение остановиться.

## Свой эксперимент

Предложи один ограничитель сверх числа шагов: максимальное время, объём прочитанных данных или число повторений одинакового предложения. Сначала опиши желаемый статус и события при срабатывании. Реализацию такого ограничителя подключим в занятиях 12–14; сегодня достаточно найти место его проверки в коде цикла.
