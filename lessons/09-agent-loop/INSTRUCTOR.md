# Проведение занятия о цикле агента

## Статус единой лаборатории

Маршрут этого урока после обновлённых 00–04 проработан в [LABORATORY_PLAN.md](LABORATORY_PLAN.md), но ещё не перенесён в рабочее поле. Ниже сохранён прежний технический маршрут; он не является готовым продолжением новой лаборатории.


Перед занятием прочитайте [руководство преподавателя](../../course/TEACHER_GUIDE.md): оно задаёт порядок подсказок, возврата к исходной ошибке и проверки самостоятельного переноса.


## Ориентация до первого задания

Начните с [введения для ученика](INTRO.md), которое выводится в консоли и повторяется командой `lesson`. Объясните, какая программа принимает команды, где находится преподаватель и когда вызывается модель. Перед каждой новой командой назовите цель, ожидаемый экран и его смысл. Попросите ученика показать нужный фрагмент и объяснить действие своими словами; только затем запрашивайте прогноз опыта.

Сначала попросите ученика назвать источник, требуемый артефакт и способ независимой приёмки. Уточните различие текста задания, предложенных действий и фактических событий. Только затем переходите к прогнозу числа шагов и разрешению цикла.

Если ученик не понимает, что читать или зачем нужна команда, вернитесь к показанному фрагменту и назначению интерфейса. Не добавляйте новые команды и не повторяйте прежнюю формулировку вместо объяснения. При неготовой среде оставьте живую часть незавершённой. Включите эту ориентацию в первые минуты плана, сохранив итоговую проверку переноса.

## Подготовка

Проверьте, что эталонный harness и модель доступны. Для этого занятия нужен исходный набор прав на чтение и запись внутри учебного каталога; расширять права ради успешного ответа нельзя. Произвольный shell и доступ к домашнему каталогу для задачи не нужны.

Прочитайте реальный код цикла. Проверьте, как учитывается шаг при ошибке формата, какие данные возвращает `read_file`, где сохраняется состояние и какие события доступны. Методичка намеренно не подменяет журнал заготовленной «типичной трассой».

Подготовщик отказывается затирать каталог с предыдущими файлами. Используйте новые имена для каждого опыта. Проверяющий код пересчитывает ожидаемый остаток из фактического источника, не доверяя статусу агента.

Готовые вспомогательные программы трёх занятий проверяются без модели:

```bash
/usr/bin/python3 lessons/09-agent-loop/check_stand.py
```

Этот запуск проверяет вычисление, ручной диспетчер, подготовку данных и приёмку артефакта. Он не запускает автоматический цикл и не подтверждает способность модели решать задачу.

## План на 80 минут

| Время | Работа |
|---|---|
| 0–10 | Ученик находит ручные действия прошлого занятия в программе цикла. |
| 10–25 | Ученик рисует ожидаемую последовательность и готовит чистый каталог. |
| 25–40 | Настоящий запуск; ученик проверяет файл и находит цепочку событий. |
| 40–55 | Ограничение одним шагом; отдельно фиксируются техническая остановка и неполная задача. |
| 55–70 | Изменение резерва при той же программе и модели. |
| 70–80 | Разбор отсутствующего источника либо обсуждение собственного ограничителя. |

## Вопросы и ответы

**Кто выбрал `write_file`?** Модель предложила действие. Harness проверил предложение и выполнил разрешённую запись.

**Почему файл появился на диске?** Сработал инструмент программы. Сам текст ответа модели файл не создаёт.

**Где находится память между шагами?** В явно поддерживаемой истории или состоянии harness. Веса при обычной генерации не меняются.

**Что означает `finish`?** Модель решила завершить работу. Успешность прикладной задачи подтверждает независимая проверка результата.

**Почему правильный отказ при недостающем файле может быть успехом опыта?** Мы проверяем реакцию на отсутствие данных. Это успех контролируемого отрицательного сценария, но не получение отчёта по исходной задаче.

**Считается ли неразбираемый JSON шагом?** Да. Иначе неверные ответы могли бы обходить бюджет.

**Доказывает ли наличие трёх сообщений агента, что было три запроса к модели?** Нет. Считают фактические запросы по журналу, а не произвольные строки ответа.

## Заблуждения и вмешательства

Если ученик считает цикл особым видом обучения, попросите найти вызов изменения весов: в этой практике его нет. Если считает статус «готово» проверкой, пусть самостоятельно вызовет `check_report.py`.

Когда маленькая модель повторяется, не выдавайте это за ожидаемый успех. Сначала проверьте, получила ли она наблюдение. Затем различите ошибку контракта, нехватку данных и недостаточную способность модели. Изменяйте только один фактор; переход на другую версию весов записывайте явно.

При опыте с одним шагом не требуйте конкретной первой команды от всех моделей. Требуйте соблюдения верхней границы обращений. Если модель сразу завершилась с неподтверждённым успехом, именно это и нужно разобрать.

## Вариант на 60 минут

Оставьте полный успешный запуск, ограничение одним шагом и разбор одной настоящей цепочки наблюдений. Изменение резерва и отсутствие источника перенесите в продолжение. Основной успешный запуск и проверка ограничителя остаются обязательными.

## Дополнение до 90 минут

Выполните сценарий с отсутствующим источником. Попросите ученика найти повторные одинаковые действия и заранее предсказать, как ограничение времени или повторов изменило бы журнал. Эти ограничения не надо писать самостоятельно на этом занятии.

## Приёмка

Нужны реальные ответы модели, правильный артефакт основного опыта, независимая проверка и подтверждённое соблюдение ограничения шагов. Не заменяйте модель запрограммированной последовательностью для выдачи успеха. Проверка механики без модели допускается отдельно и подписывается как проверка стенда.

## Совместное наблюдение в терминале

Используйте [общий порядок совместного занятия](../../course/TERMINAL_CLASSROOM.md). Ученик открывает `./lab classroom start --lesson 09`. Преподаватель находит сессию через `./lab classroom list`, читает события через `observe SESSION --json` и просит прогноз до первого запуска.

Для этого этапа исходный набор компонентов: `./lab classroom permit SESSION --capabilities doctor,complete,agent`. После проверки подготовки преподаватель выполняет `./lab classroom resume SESSION`. На разборе результата он использует `pause`, для прерывания активного опыта — `stop` и проверяет фактическое подтверждение.

Советы передавайте через `./lab classroom advise SESSION --message 'Текст следующего вопроса или опыта'`. Ученик отвечает и меняет вход самостоятельно. Дополнительные программы из методички, не подключённые к диспетчеру, обсуждайте отдельно: открытая консоль сама по себе не даёт наблюдение и остановку всех процессов ноутбука.
