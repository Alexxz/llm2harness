# Урок 08. Кто на самом деле читает файл

В уроке 07 внешняя программа проверяла ответ, а человек возвращал результат модели. Теперь свяжем модель с первым инструментом: она предложит чтение файла, ты запустишь готовую программу чтения и явно передашь полученные данные следующим запросом.

Инструмент здесь — обычный код с определённым входом и результатом. Текст `read_file` в ответе модели является предложением. Он становится настоящим чтением только после проверки и вызова программы. Для первой практики эту связь выполняет человек, чтобы увидеть каждый переход.

Работаем с выдуманными складскими данными. Готовый инструмент умеет читать только согласованный источник. Произвольные команды и код из ответа модели не исполняются. Обратная связь — это сохранённый фактический результат инструмента, который затем добавляют в новый текст для модели.

Учебная консоль показывает запросы и ведёт журнал совместной работы с преподавателем в чате. Сервер модели находится отдельно. Ручной инструмент и конструктор следующего входа — отдельные программы из README в обычном shell; сначала разберём их условия и наблюдение. Само открытие консоли не делает все внешние процессы управляемыми.

Для живой части нужны подготовленные веса и работающий сервер. Без них можно исследовать контракт готового инструмента на явно заданных входах, но это ещё не получение предложения от модели. Ошибку чтения нельзя заменять придуманными данными.

## Первое действие

Начнём с того, какую информацию собираемся дать модели. Команда `show` только печатает подготовленный запрос:

```text
show
```

Прочитай задачу и описание разрешённого действия. Раздели для себя: какие сведения уже записаны во входе, а что требуется получить из источника. Этой командой файл не читается и запрос модели не выполняется.

Расскажи преподавателю в чате, где сейчас находятся сведения для расчёта и что должно произойти до их использования в ответе. Так мы сможем проследить настоящий переход от предложения к исполнению, прежде чем запускать инструмент. Ответы и вопросы пиши в канале преподавателя. Преподаватель сам прочитает результаты опытов в журнале.

Команда `lesson` повторяет введение. README даёт последующие этапы: предложение, ручное чтение, возврат наблюдения и проверку ответа.
