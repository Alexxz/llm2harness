# Первый инструмент и ручная обратная связь

## Статус единой лаборатории

Маршрут этого урока после обновлённых 00–04 проработан в [LABORATORY_PLAN.md](LABORATORY_PLAN.md), но ещё не перенесён в рабочее поле. Ниже сохранён прежний технический маршрут; он не является готовым продолжением новой лаборатории.


Начни с [введения в урок](INTRO.md): оно объясняет новый механизм, роль консоли и первое действие до выполнения команд из подробного маршрута ниже.

Модель предложит прочитать файл, а ты вручную выполнишь строго ограниченный инструмент и вернёшь результат следующим запросом. Так ты сам побудешь циклом агента и увидишь каждую границу: текст действия, проверка разрешения, реальное чтение и новое решение модели.

Для совместной работы открой [учебную консоль с преподавателем](../../course/TERMINAL_CLASSROOM.md): `./lab classroom start --lesson 08` из корня проекта. Промпты, явные запуски и советы этой сессии видны преподавателю; обычные команды других терминалов в журнал не попадают.


## Цель

Показать, что текст `read_file` сам ничего не читает. Внешняя программа исполняет разрешённое действие, а модель получает наблюдение только тогда, когда программа или человек включит его в следующий вход.

## Перед началом

Заверши занятие 07 и подготовь тот же сервер модели на `http://127.0.0.1:8088`. Работай из корня проекта. В этом занятии не требуется контейнер: модель не генерирует исполняемый код, а готовый учебный инструмент только читает синтетический JSON. В инструменте нет shell, `eval`, произвольных команд и произвольного пути из ответа модели.

Прочитай [исходные данные](fixtures/stock.json), но не вставляй их в первый запрос к модели. Они должны попасть к ней через результат инструмента. Единственный разрешённый логический путь — `stock.json`. Его сопоставление с настоящим файлом хранится в [готовой программе](manual_tool.py) и не определяется ответом модели.

```bash
mkdir -p results/lesson08
/usr/bin/python3 -m coursekit prompt 08 baseline
```

Запиши версию модели и параметры: одна и та же модель, `temperature=0`, `seed=42`, максимум 256 новых токенов.

## План занятия

| Минуты | Работа |
|---|---|
| 0–10 | Предположи, в какой момент модель получает данные файла. |
| 10–25 | Получи предложение действия и проверь его форму. |
| 25–40 | Вручную исполни чтение и исследуй настоящий результат. |
| 40–55 | Верни результат модели и независимо проверь ответ. |
| 55–70 | Убери наблюдение, затем воспроизведи отказ политики. |
| 70–80 | Нарисуй последовательность обмена и предложи собственный опыт. |

## Опыты

### Получить предложение действия

В первом запросе есть имя файла, задача и описание единственного действия. Самих чисел нет.

```bash
/usr/bin/python3 -m coursekit complete --prompt-file lessons/08-first-tool/prompts/baseline.txt --endpoint http://127.0.0.1:8088 --max-tokens 256 --temperature 0 --seed 42 --schema lessons/08-first-tool/action.schema.json --output results/lesson08/proposal.json
```

Прочитай поле `text` в результате. Ожидается объект с `action=read_file` и `arguments.path=stock.json`. На этом этапе файл ещё не прочитан инструментом. Если вызова программы чтения нет, успешного чтения тоже нет, независимо от формулировок ответа.

### Человек исполняет разрешённое действие

Сначала найди в `manual_tool.py` проверку полного объекта действия. Затем выполни:

```bash
/usr/bin/python3 lessons/08-first-tool/manual_tool.py --proposal results/lesson08/proposal.json --output results/lesson08/observation.json
```

Это реальный вызов готового инструмента. Он читает синтетические данные из `fixtures/stock.json` и возвращает их в `result`, с `ok=true`. Текст программы не получен от модели и не меняется между запросами. Предложение обрабатывается как данные JSON, а не как команда терминала.

Флаги `--source` и `--output` задаёшь ты как оператор. Модель не может подменить настоящий путь через `arguments.path`. Это небольшой диспетчер с одним разрешением, а не изоляция операционной системы.

### Вернуть фактическое наблюдение

Готовый конструктор собирает новый текст: исходная задача, предыдущее действие и фактический результат. Он ничего не спрашивает у модели.

```bash
/usr/bin/python3 lessons/08-first-tool/make_feedback.py --observation results/lesson08/observation.json --output results/lesson08/with-result.txt
/usr/bin/python3 -m coursekit complete --prompt-file results/lesson08/with-result.txt --endpoint http://127.0.0.1:8088 --max-tokens 256 --temperature 0 --seed 42 --output results/lesson08/answer.json
/usr/bin/python3 lessons/07-reasoning/check_inventory.py --response results/lesson08/answer.json
```

Ожидаемые числа для этого источника: 159 физически и 144 доступно. Отметь в новом промпте конкретные строки, из которых модель могла получить исходные числа. Корректный результат чтения не гарантирует корректного арифметического ответа; последняя команда проверяет эту часть отдельно.

### Контроль без наблюдения

Сначала прочитай [вариант промпта](prompts/variation.txt): в нём прямо сказано, что предложенное чтение не выполнено. Можно отправить его как отдельный опыт:

```bash
/usr/bin/python3 -m coursekit complete --prompt-file lessons/08-first-tool/prompts/variation.txt --endpoint http://127.0.0.1:8088 --max-tokens 256 --temperature 0 --seed 42 --output results/lesson08/no-result.json
```

Для более строгого сравнения используй одинаковый конструктор двух входов, меняя только блок наблюдения. Первый вход уже лежит в `with-result.txt`. Второй создаётся из явно подписанного синтетического отсутствия результата:

```bash
/usr/bin/python3 lessons/08-first-tool/make_feedback.py --observation lessons/08-first-tool/fixtures/not_executed.json --output results/lesson08/without-result.txt
/usr/bin/python3 -m coursekit complete --prompt-file results/lesson08/without-result.txt --endpoint http://127.0.0.1:8088 --max-tokens 256 --temperature 0 --seed 42 --output results/lesson08/without-result-answer.json
```

Во втором входе ответ должен сообщить об отсутствии результата, а не выдумать числа. Если модель всё же назовёт 159 и 144, это не доказательство чтения: фактического вызова не было. Проверь, нет ли этих значений в отправленном тексте, и запиши неподтверждённое утверждение модели.

`not_executed.json` — контролируемая фикстура. Её нельзя учитывать как реальный ответ инструмента или модели.

### Проверить отказ программы

```bash
/usr/bin/python3 lessons/08-first-tool/manual_tool.py --proposal lessons/08-first-tool/fixtures/read_proposal.json
/usr/bin/python3 lessons/08-first-tool/manual_tool.py --proposal lessons/08-first-tool/fixtures/denied_proposal.json --output results/lesson08/denied.json
```

Вторая команда должна вернуть `ok=false`, `error=policy_denied` и код 1. Имя `../outside.txt` не используется для чтения: запрет проверяется до открытия источника. Заданные предложения нужны для проверки программы, а не для измерения склонности модели нарушать правила.

## Ожидаемые наблюдения

- Одинаковые слова `read_file` могут быть просто текстом или реально обработанным действием. Отличие видно по фактическому вызову инструмента и его наблюдению.
- На первом шаге модель получает имя и контракт инструмента. Данные файла появляются в её входе только на следующем шаге.
- Программа независимо от модели отклоняет всё, кроме единственного разрешённого действия.
- Возврат ошибки вместо данных меняет доступные сведения, но не веса модели.

## Если результат отличается

Если действие не соответствует схеме, сохрани ответ и проверь, действительно ли один и тот же сервер поддерживает ограничение по схеме. Для исследования диспетчера используй отдельно подписанную корректную фикстуру, но не объявляй её удачным ответом модели.

Если чтение не удалось, посмотри `error` и путь источника, выбранный тобой. Не заменяй ошибку выдуманным успешным наблюдением. Верни фактическую ошибку через тот же конструктор; корректный следующий ответ должен признать недостаток данных.

Если модель проигнорировала наблюдение или ошиблась при расчёте, это ограничение данного запроса. Исправление промпта, независимое вычисление и новое обучение — разные следующие эксперименты; не меняй их одновременно.

## Что сохранить

Сохрани предложение действия, JSON наблюдения, оба входа с наблюдением и без него, настоящие ответы модели, независимую арифметическую проверку и отказ диспетчера. Отдельно подпиши шаги, которые выполнил человек.

## Критерии завершения

1. Получено и сохранено настоящее предложение действия от модели.
2. Ученик вручную выполнил диспетчер и передал его реальное наблюдение следующему запросу.
3. Финальный ответ независимо проверен; возможная ошибка модели честно зафиксирована.
4. Контроль без данных выявляет отсутствие основания для числового ответа.
5. Запрещённое предложение отклонено программой до чтения.
6. Ученик различает контракт действия, фактическое исполнение и обратную связь выполнения.

## Свой эксперимент

Создай копию синтетического источника в `results/lesson08`, поменяй только `reserved` и выбери её через `--source`. Повтори чтение и передачу наблюдения с теми же весами и промптом. Прежде чем делать запрос, предскажи: физический остаток должен остаться прежним, доступный — измениться на величину изменения резерва. После опыта проверь числа самостоятельно.
