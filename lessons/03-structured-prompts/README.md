# Структурированный ответ: просьба, пример и проверка

## Цель

Получить данные о напитке и количестве чашек, отличить JSON от нужных полей и правильных сведений, сравнить два промпта на настоящих ответах. Примеры меняют вход, проверка оценивает выход; веса здесь не меняются.

## Перед началом

Уроки 01 и 02 завершены. Используем тот же подготовленный локальный сервер Qwen base и преподавателя через прямой преподаватель. Личный API OpenAI, смена ученической модели и ручная работа с файлами не нужны.

Запуск из корня курса: `./lab classroom start --lesson 03 --split`.

Преподаватель слева (F2), опыты справа (F3), помощь Ctrl+h, последний ответ F4, редактор входа F10, свободная песочница F9. В редакторе F5 сохраняет, Esc отменяет. Генерация запускается отдельно командой run. В песочнице F5 имеет другое, подписанное на экране действие — запрос.

| Время | Работа |

## Опыты

Преподаватель выдаёт по одному ближайшему действию с объяснением; это справочный маршрут, не список для слепого выполнения.

1. show показывает просьбу вернуть drink и cups для заявки «Две чашки чая». run получает настоящий ответ. Перед запуском преподаватель открывает допуск.
2. После объяснения трёх уровней check проверяет последний сохранённый ответ. Команда не вызывает модель, не вырезает JSON из прозы и не чинит ошибки. «Не оценивалось» отличается от «нет».
3. load variation добавляет один пример про три чашки кофе. Заявка и параметры остаются прежними. Можно сразу run, если преподаватель заранее разрешил его; ждать между load и run не нужно.
4. compare показывает полные входы/ответы обоих опытов, настройки и проверки. Команда локальная. F4 открывает это сравнение в большом окне с прокруткой; Esc закрывает. Исходные результаты остаются в журнале преподавателя.
5. F10 открывает текущий вход. Измените только напиток или количество в строке «Текущая заявка», сохраните F5, выполните run, затем check. Преподаватель поможет разобрать результат.

Значение drink должно быть tea или coffee; cups — целое число от 1. Ровно два поля. Например, {"drink":"tea","cups":"2"} — JSON, но cups здесь строка. {"drink":"coffee","cups":2} подходит по форме, однако неверно передаёт заявку о чае. Это придуманные примеры для объяснения.

## Ожидаемые наблюдения

На авторской пробе оба промпта дали правильные сведения. Разная запись с переносами или без них не означает разное содержание. На одном случае нельзя доказать общую надёжность или пользу примеров. Невалидный ответ модели тоже подходит для изучения проверки.

## Если результат отличается

Лишние слова делают весь ответ не одним JSON. При ошибке синтаксиса поля и смысл ещё не проверены. При обрыве смотрим предел длины: если его меняем, оба сравниваемых промпта повторяем с одинаковым новым пределом. Проверка смысла автоматически поддерживает только простые заявки: число цифрами или словами один–десять, чашки/чашка/чашку, чай или кофе. Если свободная формулировка не распознана, check честно предлагает разбор с преподавателем.

## Что сохранить

Стенд автоматически хранит фактические входы, исходные ответы, настройки и отчёты check/compare. Не перепечатывайте ответы, не копируйте файлы и не исправляйте результат перед проверкой. Проверка всегда относится к входу того опыта, даже если следующий вход уже отредактирован.

## Критерии завершения

Есть два настоящих сопоставимых ответа и собственная вариация заявки. Ученик на своих наблюдениях отличает форму от смысла и объясняет, что пример добавлен в контекст, а не в веса. Корректный JSON в каждой попытке не обязателен. Преподаватель явно объявляет завершение после обсуждения.

## Свой эксперимент

Можно изменить только «чая» на «кофе» или «Две» на «Три». Можно предложить другую формулировку; автоматический оценщик ограничен, а преподаватель может разобрать её смысл. F9 разрешает свободно играть, но результаты песочницы отдельно помечены и не заменяют обязательные опыты автоматически.

Расширенные материалы fixtures/, schema.json, render_cases.py и score.py сохранены для необязательной практики с тремя полями, null и urgent. Их синтетические ответы не являются результатами модели. Основной урок использует core-schema.json и не требует этих файлов.
