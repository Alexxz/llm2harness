# Объяснения перед практикой

## Зачем структура

Программа может прочитать поле cups и показать количество чашек. Из свободной фразы «Кажется, вам нужно две чашки» число ещё приходится извлекать. JSON даёт соглашение об именах полей и записи значений; это текстовый формат, а не отдельный интеллект. Разобранный пример: {"drink":"tea","cups":2}. Строки заключены в двойные кавычки; 2 без кавычек — число. Порядок полей и пробелы не меняют значения.

## Три разных проверки

Все примеры ниже придуманы для объяснения, а не получены от модели. Заявка одна: «Две чашки чая».

- «Вот заказ: {"drink":"tea","cups":2}» — весь текст не является одним JSON: перед объектом пояснение. Проверка не вырезает из него удобный фрагмент.
- {"drink":"tea","cups":"2"} — JSON читается, но cups содержит строку вместо числа. То же касается отсутствующего или лишнего поля.
- {"drink":"coffee","cups":2} — JSON и поля подходят, но напиток неверен. Структура не гарантирует смысл.
- {"drink":"tea","cups":2} — все три проверки проходят для этой заявки. Это не доказательство успеха на любых будущих заявках.

check читает неизменённый сохранённый ответ и исходный запрос именно этого опыта, даже если ученик уже изменил следующий вход. При ошибке раннего уровня следующие уровни показывают «не оценивалось». При свободной неизвестной заявке автоматическая проверка смысла также честно недоступна; преподаватель разбирает её с учеником.

## Что меняет пример

baseline задаёт правила. variation сохраняет правила и ту же заявку, но добавляет один разобранный пример про три чашки кофе. Модель может продолжить по его образцу; это пример в контексте, а не дообучение. Веса, сервер, temperature, seed и max_tokens в паре сохраняются. На авторском пилоте оба ответа были правильными: различались переносы и пробелы. Поэтому нельзя утверждать, что пример повысил качество. На одном случае вообще нельзя измерить общую надёжность.

## Проверка и ограничение генерации

Локальная проверка запускается после ответа. Она может сообщить об ошибке, но исходный текст уже создан. В этом уроке schema в модельном запросе остаётся null. Принуждение к форме при генерации — отдельный урок 06; даже оно не гарантирует правильный напиток. Дообучение меняет веса/адаптер и будет отдельным опытом.

## Свободный опыт

F10 открывает вход урока. Нужно изменить только строку «Текущая заявка»: например, заменить чая на кофе или Две на Пять. F5 сохраняет без генерации; Esc отменяет. После отдельного run команда check проверяет новый результат. Поддерживаемые автоматические примеры: «Две чашки чая», «Пять чашек кофе», «3 чашки кофе». Для произвольной формулировки не обещать автоматическую проверку смысла. F9 — отдельная свободная песочница, не основной учебный вход.
