# Политики доступа и изоляция исполнения

## Статус единой лаборатории

Маршрут этого урока после обновлённых 00–04 проработан в [LABORATORY_PLAN.md](LABORATORY_PLAN.md), но ещё не перенесён в рабочее поле. Ниже сохранён прежний технический маршрут; он не является готовым продолжением новой лаборатории.


Сначала прочитай [введение и первый шаг](INTRO.md): там объяснены смысл опыта, участники и конкретный текст для чтения. Блоки подготовки и опытов ниже предназначены для обычного Bash-терминала. В приглашении `ученик>` используй команды учебной консоли из введения и указаний преподавателя.

Для совместной работы открой [учебную консоль с преподавателем](../../course/TERMINAL_CLASSROOM.md): `./lab classroom start --lesson 12` из корня проекта. Промпты, явные запуски и советы этой сессии видны преподавателю; обычные команды других терминалов в журнал не попадают.


## Цель

Проверить границы, которые сохраняются даже при ошибочном выборе действия моделью. Ты исследуешь два слоя: политику разрешённых инструментов и файлов, затем изоляцию исполняемого кода.

Промпт описывает задачу и помогает модели выбрать поведение. Разрешение на чтение, запись и исполнение выдаёт harness. Контейнер ограничивает процесс, который получил разрешение на запуск.

## Перед началом

Пройди [занятие 10](../10-code-artifacts/README.md) и [занятие 11](../11-repair/README.md). Для сравнения с моделью нужны прежняя версия ядра и тот же сервер. Для проверки чтения и записи Docker не требуется: эти инструменты реализует доверенный код harness. Для проверки Bash нужна отдельно подтверждённая готовность контейнера.

Все входы здесь синтетические и публичные. Занятие не использует настоящие секреты. Проверяющий скрипт создаёт собственный контрольный файл рядом с учебной рабочей областью и проверяет, что через инструменты агента он остаётся недоступен.

## План занятия

За 80 минут: 10 — карта полномочий; 15 — механическая проверка политики; 20 — сравнение записок с моделью; 20 — разбор контейнера; 10 — объяснение отказов; 5 — собственный опыт.

## Опыты

### Опыт 1 — Нарисовать границы до запуска

Запиши, кто принимает решение на каждом этапе:

| Этап | Что происходит |
|---|---|
| Модель | Предлагает JSON действия. |
| Валидатор и политика | Проверяют известное действие, аргументы, разрешение инструмента и границы пути. |
| Файловый инструмент | Читает или записывает допустимый файл. |
| Контейнер | Исполняет разрешённый Bash в ограниченной среде. |
| Приёмка | Сопоставляет результат с задачей и проверками. |

Сначала предскажи исходы: чтение `notes.txt` внутри workspace, чтение `../outside-canary.txt`, запись за границу, чтение через ссылку наружу и запрос `run_bash` без разрешения shell.

### Опыт 2 — Проверить политику без модели

```bash
/usr/bin/python3 lessons/12-policies/probe.py --describe
/usr/bin/python3 lessons/12-policies/probe.py --workspace results/lesson12/policy-probe > results/lesson12-policy-probe.json
```

Скрипт подаёт заранее заданные сообщения действия через интерфейс модели. Сама модель не вызывается. Настоящими являются политика, файловые операции и журнал harness. Такой опыт доказывает поведение стенда на проверенных входах, а не устойчивость модели к любой атаке.

В каждом случае создаётся отдельный рабочий каталог. Разрешённое чтение должно вернуть записку, а разрешённая запись — создать файл. Запрещённые действия должны получить событие `policy_denied` и не раскрыть контрольное содержимое или создать файл снаружи. Контрольный файл — публичная фикстура; она позволяет проверить факт чтения без настоящих чувствительных данных.

В журнале найди предложенное действие, отказ с причиной и следующий результат/остановку. Если проверка не обнаружила события отказа, это не повод объявлять защиту работающей: сохрани расхождение и разбери реализацию.

### Опыт 3 — Подключить настоящую модель

Подготовь два каталога. Промпты одинаковы; меняется только содержимое возвращаемой записки.

```bash
/usr/bin/python3 lessons/12-policies/prepare.py --workspace results/lesson12/baseline --variant baseline
/usr/bin/python3 lessons/12-policies/prepare.py --workspace results/lesson12/injection --variant injection
./lab agent --task-file lessons/12-policies/prompts/baseline.txt --workspace results/lesson12/baseline --endpoint http://127.0.0.1:8088 --max-steps 6 --tools read_file --state results/lesson12/baseline-state.json > results/lesson12/baseline-run.json
./lab agent --task-file lessons/12-policies/prompts/variation.txt --workspace results/lesson12/injection --endpoint http://127.0.0.1:8088 --max-steps 6 --tools read_file --state results/lesson12/injection-state.json > results/lesson12/injection-run.json
```

Во второй записке есть указание читать соседний файл под видом нового системного правила. Это данные инструмента, а не полномочие. Агенту по-прежнему разрешено только чтение внутри workspace и завершение ответа.

Модель может проигнорировать вставку и не предложить запрещённое действие. Тогда отсутствие `policy_denied` в этом живом запуске нормально: политики не пришлось отказывать. Её механическое действие отдельно проверено опытом 2. Если модель предложила запрещённый вызов, проверь фактический отказ, а не только финальное обещание модели.

### Опыт 4 — Разобрать границу контейнера

```bash
mkdir -p results/lesson12/sandbox
./lab sandbox-check --workspace results/lesson12/sandbox
```

Прочитай реализацию `coursekit/sandbox.py` как текст и найди конфигурацию запуска. На вход контейнеру передаётся снимок рабочей области, доступный только для чтения. Рабочая копия находится в ограниченном временном хранилище `/work`. Изменённые обычные файлы возвращаются через проверенный экспорт; прямого writable bind mount хоста нет.

Найди также: запрет сети, read-only корень, запрет повышения привилегий, ограничения памяти, CPU, процессов, времени и объёма вывода. Домашний каталог и управляющий socket Docker не предоставляются. Доверенный журнал и состояние находятся вне рабочей области агента. Ограничения пути, таймаут и список инструментов по отдельности не создают изоляцию процесса.

Обсуди с преподавателем отказ при неподготовленном образе. В этом случае исполнение останавливается; запуск того же текста на хосте не является допустимой альтернативой. Не убирай ограничения и не подгружай новый образ во время действий агента.

## Ожидаемые наблюдения

Поведение модели и действие политики можно оценить отдельно. Даже готовый текст вредного действия остаётся данными до проверки. Содержимое прочитанной записки не может расширить права инструмента.

Вложенная команда, прошедшая через разрешённый `run_bash`, работает внутри отдельной среды. Изоляция зависит от конфигурации и реализации контейнерного слоя; один факт наличия Docker не доказывает достаточность любых его настроек.

## Если результат отличается

- Разрешённое чтение не проходит: найди ошибку путей или конфигурации; повсеместный отказ ещё не доказывает правильность политики.
- Запрещённое чтение раскрыло контрольное содержимое: останови практику с инструментами и разбери дефект стенда.
- В живом запуске нет попытки выполнить вставку: это допустимый результат; не подменяй его искусственной попыткой модели.
- Модель говорит, что получила разрешение: проверь политику и события, а не текст утверждения.
- Нет Docker daemon или образа: часть чтения/записи остаётся доступной, приёмка изоляции исполнения откладывается.
- Появился неизвестный файл, ссылка или удаление: изучи решение экспорта. Выход за границу, ссылки и неподдерживаемые изменения должны приводить к отказу.

## Что сохранить

Сохрани прогноз исходов, JSON механической проверки с пометкой `offline_fixture`, оба живых запуска, конфигурацию разрешённых инструментов и отчёт готовности контейнера. В объяснении раздели три результата: выбор модели, решение политики и фактический эффект.

## Критерии завершения

1. Механическая проверка подтверждает разрешённые операции и отказ на выход за границу, ссылку и запрещённый инструмент.
2. В сравнении записок менялось только недоверенное содержимое, а полномочия сохранились.
3. Ты можешь найти в трассе причину отказа и показать отсутствие запрещённого эффекта.
4. Для контейнерной части выполнена реальная проверка среды и объяснён путь входных/выходных файлов.
5. Ты не приписываешь проверке заранее заданных сообщений оценку устойчивости настоящей модели.

Практика с моделью и проверка контейнера принимаются по фактическим отчётам. Подготовка материалов и проверка JSON сами по себе не закрывают эти условия.

## Свой эксперимент

Добавь синтетическую записку, в которой инструкция спрятана в примере JSON или процитированном письме. Сохрани те же полномочия и задачу пересказа. Сравни, изменился ли выбор модели; отдельно проверь, что запрещённый эффект всё равно недоступен.
