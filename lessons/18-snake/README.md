# Агент создаёт и проверяет Змейку

## Статус единой лаборатории

Маршрут этого урока после обновлённых 00–04 проработан в [LABORATORY_PLAN.md](LABORATORY_PLAN.md), но ещё не перенесён в рабочее поле. Ниже сохранён прежний технический маршрут; он не является готовым продолжением новой лаборатории.


Сначала прочитай [введение и первый шаг](INTRO.md): там объяснены смысл опыта, участники и конкретный текст для чтения. Блоки подготовки и опытов ниже предназначены для обычного Bash-терминала. В приглашении `ученик>` используй команды учебной консоли из введения и указаний преподавателя.

В финальном занятии наш агент работает с согласованной спецификацией, создаёт игру, получает реальные результаты проверок и исправляет ошибки. Ты наблюдаешь механизм, проверяешь результат независимо и играешь в терминале.

Для совместной работы открой [учебную консоль с преподавателем](../../course/TERMINAL_CLASSROOM.md): `./lab classroom start --lesson 18 --sandbox-image llm-course-sandbox:1.0` из корня проекта. Промпты, явные запуски и советы этой сессии видны преподавателю; обычные команды других терминалов в журнал не попадают.


## Цель

Связать весь курс в одной задаче: ядро модели выбирает действия, harness контролирует исполнение и состояние, инструменты дают наблюдения, а пользователь принимает продукт по согласованным критериям.

## Перед началом

Занятие 17 закончено явным согласованием спецификации. В work/snake находятся принятые требования и OpenSpec-артефакты. Защищённые требования, критерии и трассы находятся вне этого каталога. Игра ещё не должна быть заранее написана преподавателем.

Нужны подготовленные модель и образ llm-course-sandbox:1.0. Образ включает необходимые инструменты заранее; сеть и получение пакетов во время действий агента запрещены. Headless-профиль в HEADLESS.md и fixtures/headless_cases.json должны соответствовать согласованным правилам.

    mkdir -p results/18
    /usr/bin/python3 -m coursekit doctor
    /usr/bin/python3 lessons/18-snake/check_snake.py --help

Подготовка образа, получение модели и длительное ожидание вычислений учитываются отдельно от 60–90 минут активного урока. Указанные ниже бюджеты — пределы опыта, а не измеренная длительность работы на твоём CPU.

## План занятия

| Минуты | Действие |
| --- | --- |
| 0–10 | Проверить критерии и предсказать последовательность действий |
| 10–35 | Агент создаёт файлы и выполняет свои проверки |
| 35–50 | Независимая проверка поведения |
| 50–65 | Исправление по реальному отчёту |
| 65–80 | Ручная игра и восстановление терминала |
| 80–90 | Разобрать трассу и принять результат |

## Опыты

### Проверка самого checker без модели

Перед настоящей приёмкой можно проверить проверяющий код на явно искусственных результатах. Эта команда не запускает игру, модель или Docker и не доказывает готовность реализации.

    /usr/bin/python3 lessons/18-snake/check_snake.py \
      --fixture-report lessons/18-snake/fixtures/synthetic-good-report.json \
      --output results/18/checker-fixture.json

В отчёте должны остаться evidence_type=offline_fixture и manual_acceptance=not_run. Тесты проверяют также, что неправильный счёт, ошибочное столкновение с освобождённым хвостом и таймаут обнаруживаются:

    /usr/bin/python3 -m unittest discover -s lessons/18-snake -p 'test_checker.py'

### Автономная реализация

    /usr/bin/python3 -m coursekit agent \
      --task-file lessons/18-snake/prompts/baseline.txt \
      --workspace work/snake \
      --endpoint http://127.0.0.1:8088 \
      --tools read_file,write_file,run_bash,ask_user,finish \
      --sandbox-image llm-course-sandbox:1.0 \
      --max-steps 48 \
      --max-requests 60 \
      --max-tokens 4096 \
      --timeout 300 \
      --deadline-seconds 1800 \
      --state results/18/implementation-state.json \
      > results/18/implementation.json

Агент должен прочитать требования, получить реальные instructions apply из OpenSpec, создать игру и выполнять проверки через контейнер. Если выяснилось содержательное противоречие, корректным результатом будет ask_user. Ответь через answer-file и возобнови тот же запуск с прежними разрешениями и образом.

Не считай число файлов мерой успеха. В трассе найди создание snake.sh, фактический запуск проверки, stdout/stderr и последующее решение модели. Текст «тесты прошли» без наблюдения инструмента недостаточен.

### Независимая автоматическая проверка

Проверяющий скрипт доверенный и находится вне каталога записи агента. Он передаёт игру в DockerSandbox и никогда не исполняет snake.sh на хосте. Для каждого сценария создаётся свежая копия одного снимка реализации; её контрольная сумма записывается в отчёт. Изменение исходных файлов во время проверки или запись файлов самой игрой в headless-режиме приводит к неуспеху, а не меняет реализацию для следующего сценария.

    /usr/bin/python3 lessons/18-snake/check_snake.py \
      --workspace work/snake \
      --image llm-course-sandbox:1.0 \
      --output results/18/acceptance.json

    jq '{evidence_type, passed, cases, manual_acceptance}' results/18/acceptance.json

Проверяются синтаксис и игровые правила: перемещение, рост и счёт, стена, столкновение с телом, освобождающийся хвост, запрет обратного поворота, выход, заполнение поля и неверные аргументы. Это независимые ожидания, заранее согласованные в занятии 17. Скрипт не использует тесты, которые модель могла переписать ради успеха.

Запуск контейнера не доказывает, что код создала модель: это подтверждается отдельной трассой. Проверка без терминала также не заменяет ручную игру.

### Исправление по отчёту

Если есть неуспех, составь results/18/repair-task.txt: текст prompts/variation.txt и реальный отчёт acceptance.json. Не переписывай показатели отчёта и не выдавай синтетический пример за настоящую ошибку.

    cat lessons/18-snake/prompts/variation.txt results/18/acceptance.json \
      > results/18/repair-task.txt

    /usr/bin/python3 -m coursekit agent \
      --task-file results/18/repair-task.txt \
      --workspace work/snake \
      --endpoint http://127.0.0.1:8088 \
      --tools read_file,write_file,run_bash,ask_user,finish \
      --sandbox-image llm-course-sandbox:1.0 \
      --max-steps 24 \
      --max-requests 30 \
      --max-tokens 4096 \
      --timeout 300 \
      --deadline-seconds 1200 \
      --state results/18/repair-state.json \
      > results/18/repair.json

Это отдельная ограниченная задача исправления. Завершённый implementation-state не возобновляют как будто он всё ещё ожидает ответ. После исправления повтори независимую проверку и сохрани новый отчёт под другим именем.

Если все проверки прошли сразу, не выдумывай неуспех. Вместо этого предложи дополнительное начальное состояние или переход и заранее вычисли ожидаемый результат. Ошибка в новом сценарии даёт настоящую обратную связь; успешный сценарий тоже является результатом.

### Проверяем настоящую игру

Запускай игру только внутри интерактивного контейнера. Подготовленный образ должен содержать stty. Перед запуском и после выхода сравни stty -g в одной и той же контейнерной TTY. Проверь обычный выход и отдельный запуск с прерыванием.

Команда ниже — доверенный ручной запуск ученика. Она монтирует только игровой каталог на чтение и не передаёт состояние harness. В контейнер передаются твои непривилегированные UID и GID: это позволяет прочитать экспортированные файлы с правами 0600 без изменения их прав на хосте. Проверь, что id -u не равен 0. Контейнер ограничен двумя минутами; при прерывании или таймауте удали только созданный для этого опыта контейнер.

    mkdir -p results/18/docker-client
    timeout --signal=TERM --kill-after=5s 120s \
      docker --config "$PWD/results/18/docker-client" run --rm -it \
      --name llm-course-snake-manual --pull=never \
      --network none --read-only --cap-drop ALL \
      --security-opt no-new-privileges \
      --pids-limit 64 --memory 256m --cpus 1 --user "$(id -u):$(id -g)" \
      --tmpfs /tmp:rw,noexec,nosuid,size=16m \
      --mount type=bind,src="$PWD/work/snake",dst=/work,readonly \
      --workdir /work --entrypoint bash llm-course-sandbox:1.0 \
      -c 'before=$(stty -g); trap '\''after=$(stty -g); if [ "$before" = "$after" ]; then printf "\nTERMINAL_RESTORED=yes\n"; else printf "\nTERMINAL_RESTORED=no\n"; fi'\'' EXIT; bash snake.sh'

Если контейнер с этим именем уже есть, сначала проверь причину предыдущего незавершённого опыта. После таймаута или прерывания:

    docker --config "$PWD/results/18/docker-client" rm -f llm-course-snake-manual

Не удаляй чужие контейнеры и не используй Docker socket внутри игрового контейнера. Обычная завершённая игра с --rm сама удаляет контейнер; сообщение «контейнер не найден» при дополнительной уборке ожидаемо.

Заполни manual-acceptance.json в отдельной копии results/18. Важно проверить реальную отзывчивость клавиш, движение и выход, а не только появление картинки. Если TERMINAL_RESTORED=no, это дефект, даже когда Docker затем восстановил внешний терминал.

## Ожидаемые наблюдения

После каждого tool-result модель видит фактическое наблюдение и выбирает следующий шаг. Веса во время цикла не меняются. Состояние позволяет объяснить каждый записанный файл и причину остановки.

Автоматический отчёт может содержать ошибки и после нескольких исправлений. Сохранение честного неуспеха и остановка по бюджету полезнее бесконечного повтора. Итоговый успех требует реальной игры, автоматических свидетельств и ручной приёмки.

## Если результат отличается

Отсутствует образ или Docker недоступен — исполнение прекращается; хост не используется как запасной путь. Не предоставляй дополнительные каталоги, сеть и привилегии ради прохождения проверки.

Проверка синтаксиса прошла, а рост неправильный — передай конкретный вход, ожидаемый переход и stdout из независимого отчёта. Если агент изменил только собственные тесты, независимая проверка должна по-прежнему обнаружить дефект.

Ошибка только в ручном режиме — опиши клавиши, наблюдаемый эффект и состояние терминала до/после; headless-отчёт этой ошибки не содержит.

## Что сохранить

Сохрани согласованную спецификацию, идентификатор модели, настройки, состояния и трассы всех запусков, автоматические отчёты до/после, ручной протокол и финальные файлы. Отдельно отметь, что завершено, что не прошло и что было остановлено по бюджету.

## Критерии завершения

- Игру создал наш агент; есть трасса чтения требований, действий и реальных проверок.
- Проверки выполнялись в контролируемом контейнере, независимая приёмка осталась вне записи агента.
- Все согласованные автоматические сценарии прошли на реальной реализации.
- Ты сыграл, проверил управление, обычный выход, прерывание и восстановление терминала.
- Реальные ошибки либо исправлены с повторной проверкой, либо явно оставлены как незавершённые.
- Ты можешь по трассе объяснить, что сделала модель, harness, OpenSpec и каждый инструмент.

## Свой эксперимент

Выбери одно новое правило, например паузу или изменение скорости. Сначала проведи короткий раунд требований, обнови OpenSpec и критерии, затем поручай изменение агенту. Сравни объём контекста, число действий и регрессии с исходной задачей.
