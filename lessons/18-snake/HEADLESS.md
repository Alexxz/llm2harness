# Контракт независимой проверки Змейки

Это предлагаемый технический контракт первой версии игры. Его согласуют в занятии 17 до реализации. Он определяет режим проверки правил без терминала и дополняет настоящий режим игры с клавиатуры.

## Программа и входы

Программа называется snake.sh и работает в Bash 5.2 без установки дополнительных библиотек. Для проверяемого режима принимаются аргументы:

    bash snake.sh --headless --width 8 --height 6 \
      --snake '3,2;2,2;1,2' --direction R \
      --food '4,2;6,3' --moves R --ticks 1

Координаты нумеруются с нуля: x от 0 до width−1, y от 0 до height−1. Ширина и высота — целые числа от 2 до 80. Список snake содержит голову первой, затем соседние клетки тела. Клетки не повторяются и находятся внутри поля. Направления: U, D, L, R.

Первый элемент food — текущая еда; следующие используются после поедания. В тестовых сценариях элементы очереди допустимы для соответствующих моментов. Если очередь закончилась, выбрать первую свободную клетку в порядке y, затем x; на полностью занятом поле еды нет. Текущая еда не может находиться в змейке.

Каждый символ moves задаёт одно действие тика: U, D, L, R или Q. Если символов меньше, чем ticks, сохраняется последнее направление. ticks — целое число от 0 до 1000. Headless-режим работает без задержек, чтения TTY и случайности.

## Правила базового профиля

- Ввод противоположного направления при длине больше единицы игнорируется.
- Каждый обычный тик перемещает голову на одну клетку.
- Поедание сохраняет хвост, увеличивает длину и счёт на единицу.
- Без поедания хвост освобождается. Переход в его прежнюю клетку разрешён.
- Выход за границу завершает игру с причиной wall. Переход через край отсутствует.
- Столкновение с оставшимся телом завершает игру с причиной self.
- После столкновения тело не перемещается в недопустимую позицию.
- Q завершает игру с причиной quit без перемещения.
- Заполнение поля даёт статус won, причину filled и food=null.
- После завершения новые тики не выполняются.

Если пользователь выбирает другие правила, меняют этот профиль и независимые ожидания перед генерацией кода. Проверка базового профиля не должна отвергать корректную реализацию другого заранее согласованного варианта.

## Выход

На stdout — по одному JSON-объекту на строку: начальный кадр tick=0, затем кадр после каждого выполненного тика. Для ticks=1 получается два кадра. После завершающего кадра дополнительных строк нет.

    {"tick":0,"width":8,"height":6,"snake":[[3,2],[2,2],[1,2]],"direction":"R","food":[4,2],"score":0,"status":"running","reason":null}

Обязательные поля: tick, width, height, snake, direction, food, score, status, reason. Дополнительные поля допустимы, если не меняют смысл обязательных.

status принимает running, game_over, quit или won. reason=null для running, wall/self для game_over, quit для quit, filled для won. После принятого поворота direction отражает принятое направление, в том числе при столкновении. Начальный score=0; счёт — число поеданий после начального кадра.

В stdout нет ANSI-последовательностей, приглашений или текстовых пояснений. Диагностика — в stderr. Корректный завершённый опыт имеет код 0. Неправильные аргументы приводят к ненулевому коду и диагностике без запуска игрового цикла. Headless-проверка не изменяет файлы: каждый сценарий получает свежую копию одной и той же реализации, а изменение этой копии считается неуспехом.

## Что проверяется отдельно

Настоящий терминальный режим: видимое поле, согласованные клавиши, движение во времени, выход, прерывание и восстановление терминала. Headless-контракт не доказывает, что эти свойства работают.
