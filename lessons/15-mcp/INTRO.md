# Урок 15. Инструмент в отдельной программе

До этого программа курса сама предоставляла агенту файловые инструменты. Теперь подключим инструмент, который живёт в другом процессе, и проследим обмен между двумя программами.

Им нужна общая договорённость: как установить связь, узнать список операций, передать аргументы и получить результат. Здесь используется MCP — протокол такого обмена. Он не обучает модель и не выполняет действие от одного упоминания имени инструмента. Позже модель предложит действие, а программа курса проведёт настоящий вызов.

Ты находишься в учебной консоли. Она хранит задачу и журнал; преподаватель читает события во время нашего общения в чате. Сервер модели и локальный MCP-сервер — отдельные программы с разными ролями. MCP-сервер этого курса умеет читать только синтетические заметки из назначенной папки.

Для первых протокольных опытов модель, сеть и Docker не нужны. Для опыта с выбором инструмента моделью понадобится её подготовленный сервер. Связь между программами и качество выбора модели проверяются отдельно; доступ к внешним системам в этом уроке не используется.

## Первый шаг

Сначала выясним, какую информацию собираемся получить, до разбора протокольных сообщений. В приглашении `ученик>` введи:

```text
show
```

Появится исходная задача о `notes.txt` с настройками управления игрой. `show` только показывает этот вход: файл не читается, MCP-вызов не происходит. Прочитай первую строку и требование к итоговому ответу.

Назови, какие факты нужно получить из заметки и какой маршрут чтения указан в этом исходном варианте. Содержимое заметки пока неизвестно, поэтому значения клавиш не угадываем. После этого разберём, как отличается прямой инструмент от вызова через отдельный сервер.

 Ответы и вопросы пиши в канале преподавателя. Преподаватель сам прочитает результаты опытов в журнале.
